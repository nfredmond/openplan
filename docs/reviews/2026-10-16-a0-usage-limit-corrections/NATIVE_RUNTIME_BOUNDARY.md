# Prepared configuration probe requires a new isolated wrapper

No SQL or runtime executes in this correction. `NATIVE_CONFIGURATION_PROBE.sql`
is a source fragment, not a ready-to-run admission packet. The historical probe
and its manually supplied `synthetic=yes` flag remain unchanged historical inputs.
They do not authorize or identify a target.

Before any future SQL, root must prepare and review a new wrapper and immutable
identity receipt. That wrapper must establish the actual disposable container ID,
stack/project label, image digest, loopback port mapping, database name/OID, session
role and fresh backend identity independently of caller-provided labels. It must
refuse a protected installation, an existing user fixture, a changed identity,
missing pins or unknown dispatch outcome. No DSN discovery, production defaults,
credential echo, shell expansion of credentials or automatic retry is permitted.

The wrapper must pin this candidate's migration and fragment hashes, then the
expected installed function definitions and proconfig after a separately authorized
isolated application. It must retain the new fixture's user/workspace/project,
connection/turn/attempt identities and private token hash without putting secrets
in process arguments or public evidence. The fragment checks the matching database,
server, role, application name, function definitions, explicit `pg_temp` ordering,
service-only execute privileges and fixture identity. Those checks supplement the
wrapper; a manually populated JSON setting does not prove target identity.

The wrapper owns a bounded transaction, lock and statement timeouts, fail-stop
execution, actual role-denial controls, unconditional rollback, unchanged original
row hashes and proof that temporary objects disappear. Run the shadowing controls
in a fresh backend before the tested functions first compile. The fragment uses
temporary application table names and temporary built-in type names, then requires
normal validator behavior, retained failure and exact replay under service_role.
No temporary row or type may acquire application authority.

Root must separately prepare harmless and targeted native mutations, preserve
failed trials, restore exact definitions/configuration in finally cleanup and prove
the restoration. Source regex tests cannot establish PostgreSQL compilation or
runtime resolution. This fragment does not close RLS, cross-user/workspace/project,
wrong token, revoked connection, stale attempt, lease, concurrency, other-provider,
version 1/API replay, route-to-database or browser acceptance. The independent
review lists those remaining boundaries. No existing protected SQL target may be
used to fill them.
