# Populated output recovery schema candidate

The initial private capture retains a 406-migration fixture and identifies only
main migrations 02 and 05 as missing. Main dae9d2457 has 408 migration files;
existing files have not changed since the retained baseline. Exact file hashes
and the fresh private dump stay bound to the selected source.

The initial native trial installs both missing migrations through the installed
CLI, verifies its no-op, recovers exact saved output under three actual access
reads, and refuses revoked access without changing the complete receipt. A new
logical database restores a fresh upgraded dump and repeats that recovery.
Neither recovery queries an engine or refetches source bytes. Original proof
databases remain retained. Owned services stop in finally.

This is a same-cluster populated fixture and a matching migration set. It does
not establish hosted data restore, global-role or key reconstruction, physical-
host recovery, whole-installation completeness, login/email, browser use,
processing-time permissions, survey accuracy or practitioner acceptance.
Both Python 3.14 and 3.11 native cohorts pass four positive controls and five
targeted failures. The positives include harmless source and SQL comments and
restored code. Missing migration 05, an RPC service using the old database,
ignored actor revocation, changed copied archive bytes and premature publication
fail at their intended assertions. Eight failure-oracle controls reject unrelated
errors. The controller restores source bytes in finally, retains every new proof
database and independently records stopped owned services.

Both parent cohorts reach the 1 GiB cap, with 2,672 and 2,318 max pressure events,
zero swap and zero OOM. These are not spare-capacity results. The selected schema
source remains pinned to dae9d2457. Later remote main41cbd5a8 adds migration 06;
this proof is not acceptance of that newer schema or current hosted data.
PR295 rejoins the new main in its separate HTTP worktree and reruns its checks.

The [native producer](native_upgrade_restore.py) and [control runner](verify_native_upgrade_controls.py) retain exact arguments and failure reasons. The [transfer package report](../2026-10-14-linux-transfer-preparation/STATUS.md) records the separate prepared archive and open host checks.
