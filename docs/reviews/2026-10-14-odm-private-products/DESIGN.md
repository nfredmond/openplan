# Private original product files

The original output intake retains a complete archive under current actor
access. The legacy worker separately downloads and extracts files, then discards
the archive. The managed continuation needs exact, recoverable product files
before preview rendering, delivery or application publication.

Reuse the original intake and its archive inventory. Select the four original
members already recognized by the installed NodeODM adapter: orthomosaic, DSM,
DTM and point cloud. The orthomosaic must be present and nonempty. Record each
optional member's absence explicitly. Do not infer the reason from a preset.

Before extraction, freeze the original engine plan, observation hash, archive
hash and size, and selected member names, sizes and hashes. Write only flat,
private files under the original runtime root. Bound reads by the retained
member size and check ownership, cancellation and deadline during copying.
Synchronize complete bytes before immutable publication. Recovery checks every
saved file; changed files refuse instead of being replaced. Interrupted private
copies can resume from the retained archive without another external download.

Check current actor access before and after materialization. Keep the original
archive and incomplete files if access ends. Publish no completion receipt after
that refusal. A recovered receipt describes private byte custody only. It grants
no callback, Storage upload, map-placement, publication or scientific permission.

Tests use the existing original-intake fixture and actual loopback archive
transport. Controls include harmless source changes and targeted faults for
selection, byte comparison, access, cancellation and unsupported claim promotion.
Separate interpreter and useful retained-output checks follow. No database,
default worker, shared UI or hosted configuration changes belong to this step.
