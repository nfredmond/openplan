# Operations and documentation consolidation proposal

Prepared 2026-09-04 from the read-only OpenPlan checkout. This supplements the unchanged `independent-engineering.md`; it does not revise that review. No checkout edits, tests, browser sessions, services, accounts, or live deployment probes were performed. Official provider documentation was checked online. The proposed free agency production path remains engineering work, not a documentation rewrite that can make an unproved deployment production-ready.

State that the documented path is local evaluation/development, with known dependencies and a separate commissioning process for agency use. Do not imply local configuration automatically becomes a supported team deployment.

Maps, geographic data retrieval, and any enabled cloud services still contact outside providers. The deployment guide lists those connections and the information they receive.” A fully offline/private map mode is not implemented in the inspected OpenPlan path.
- `Step 1`: lead with the tested Linux reference environment and an open Docker Engine path. Docker Desktop is not free for government entities under its current terms. Keep Windows/macOS instructions only with an explicit licensing boundary and unproved-install status; do not imply a newly selected alternative such as Podman or Colima has been tested. State Node 24 as the current CI reference instead of mixing “LTS,” an Ubuntu Node 22 install script, a Node 20 minimum and npm 11 assumptions. Verify compatibility separately before changing the actual minimum.
- `Step 2`: use the lockfile-preserving `npm ci` for a checkout with the tracked lockfile. Remove blanket reassurance that all install-script warnings are harmless. Refer unexplained warnings to contributor/dependency guidance. State Git as a prerequisite; the existing Node/Docker-only introduction omits it.
- `Step 4`: call Mapbox an external provider with account/terms/usage limits, not simply a free map service. Its token is needed for the currently implemented map surfaces, but not for booting every app route. Reconcile Census requirements with actual feature preflight; README says maps/engagement/grants/reports do not need it while SELF_HOSTING says equity/corridor data do. Avoid asserting current provider behavior from an old anecdote. Separate key availability from requested-data availability.
- `Step 5`: use `supabase migration up --local` rather than make destructive `db reset` the ordinary first-install step. Remove stale “~157 tables” counts. If troubleshooting ever needs reset, isolate it in explicit disposable-data guidance, not the happy path.
- `Step 6`: use one consistent configured origin, noting the local Auth callback configuration currently uses `127.0.0.1:3000`. Explain that `npm run dev` executes `predev` migration sync, while `npm start` does not. Do not equate a Ready line with working authentication or saved data.

Document re-creation of the affected service after environment changes, with data-volume preservation. Distinguish `modeling:up` county-onramp container from `modeling:local` paired AequilibraE/ActivitySim pollers. One does not provision the other.
- `If something goes wrong`: reduce to local evaluation issues plus links. Do not describe `doctor` as an outcome or security test. It checks settings, selected local services and shallow HTTP liveness, not a completed model or valid callback token.
- `How long a model run takes`: keep no accuracy sacrifice, but replace absolute “a browser tab or serverless timeout can never cut one short” with actual asynchronous-worker behavior and known lifecycle/recovery limits. Model reaping currently has the separate risk identified in the independent review.

## Contributor minimum QA and honest CI language

CONTRIBUTING should link to the binding contract/manual and remove its superseded absolute prohibition on new modules. State full all-state/DC v1 intent, honest interim gaps, and planner-visible evidence requirements. Avoid “then expand if feasible” as the final pre-review standard.

For a code change, run meaningful focused regression and lint/type/build checks as appropriate, then the repository's `qa:gate` before review. Explain that the gate currently includes direction review, lint, dead-code check, Vitest, conditional local RLS, production dependency audit and build. A skipped local RLS check is unproved isolation. Changes to migrations/auth/storage/public data need live RLS; worker changes need actual affected worker suites and full worker evidence at the release checkpoint; visible workflows need identified-commit desktop/390px/keyboard and artifact checks; schema/recovery changes need populated upgrade and restore evidence. Every new/changed guard needs a meaningful failing mutation and a known-surviving no-op where using a mutation harness. Do not call all tests passed when required environments are missing.

Current CI blind spots to state plainly: four worker families are not executed in CI; import-only checks skip absent environments; live RLS is a separate workflow; browser smokes are nightly/manual and omit a workspace URL-isolation smoke; upgrade runs on selected triggers and representative records; restore is selective and periodic; no unified release result presently proves all required evidence on the same commit. Root must verify current remote runs and branch protection after handoff. A doc edit should not claim those mechanics were fixed.

SECURITY should retain private GitHub reporting and the no-public-secrets rule, with scope extended explicitly to worker/callback, external-service and local-artifact boundaries. Do not claim private reporting is enabled without verifying repository settings. LICENSE should remain unchanged. LICENSE-NOTICE's “Nat Ford managed hosting … may be offered commercially” is inconsistent with the present contributor positioning and no-offering docs; replace it with a neutral statement about Apache license rights and separate third-party services, without inventing a new product offering or restricting the license.

Its root LICENSE/notice say Apache-2.0 with third-party and confidential-material exclusions. The README claims end-to-end integration, but I did not independently rerun it. It also labels auth-gated PR E2E deferred and its quickstart exposes a NodeODM port broadly. Do not import that operational example as a secure OpenPlan default. Use the existing processing contract rather than build another aerial module, and inspect the actual chosen files and upstream licenses before any future reuse.

## Safe handoff sequence

1. Land truthful wording and canonical document ownership without changing architecture or claiming new proof. Preserve independent and dated evidence unchanged.
2. Make only separately justified guard corrections that enforce actual paths, commands, provider boundaries and evidence states; mutation-test them after the active workflow releases the tree.
3. Record engineering gaps for full production self-hosting, map-provider independence, durable job recovery and full backup/restore. Documentation cannot close them.
4. Commission a genuine free reference deployment with a stranger and representative saved work; record exact environment, network/egress behavior, recovery artifacts and remaining failures. Then promote that path to supported agency production guidance.
