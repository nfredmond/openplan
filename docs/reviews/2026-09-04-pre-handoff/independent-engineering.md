# Independent engineering and whole-product direction review

Date: 2026-09-04. Inspected commit: `ad640ce7164cbea55bddd30341748e5f48639410`, package v0.44.0. Reviewer began with the neutral direction packet and did not read another current independent reviewer's conclusions. This report is advisory and preserves the full v1 contract.

OpenPlan has substantial planning and evidence infrastructure, but its claim to be a free, self-service operating system is not yet supported by its default installation path, privacy disclosures, or long-job lifecycle. My next completed outcome would be a small agency independently operating and recovering a real planning record on a fully free reference deployment. This should include a complete planner handoff, rather than an installer-only demonstration. Scientific modeling, nationwide statutory depth, and every planning practice remain mandatory v1 programs.

## Material engineering findings

### E1. The documented free deployment path does not work for the whole target audience

Evidence: `README.md`, one-computer installation, calls Docker Desktop a free prerequisite and directs Windows/macOS users to install it. Current [Docker Desktop licensing documentation](https://docs.docker.com/subscription-billing/desktop-license/) requires paid subscriptions for government entities. This directly affects cities, counties, states, and agencies central to v1. Linux Docker Engine is a distinct open-source option under its [documented Apache license](https://docs.docker.com/engine/).

`openplan/docs/FIRST_DEPLOYMENT.md:10` promises four free accounts, including Vercel. `SELF_HOSTING.md:255` says Vercel's free tier is sufficient for a small agency. Current [Vercel Hobby documentation](https://vercel.com/docs/plans/hobby) limits that plan to non-commercial personal use. A consultancy's ordinary operational deployment cannot be assumed eligible; agency eligibility should not be asserted without support. Local Node hosting is already described, so this is a broken default and unsupported assurance, not proof that free operation is impossible.

`openplan/package.json` depends on Mapbox GL 3.x. Multiple maps and the central basemap registry use Mapbox-hosted styles. `scripts/doctor.mjs:60` says missing a token leaves maps blank; self-hosting docs mark it required in practice. Mapbox's [license file](https://github.com/mapbox/mapbox-gl-js/blob/main/LICENSE.txt) subjects newer GL JS releases to Mapbox terms. OpenPlan's own Apache license does not turn this dependency into Apache-licensed software. I am not alleging infringement. I am identifying an unproven fully free deployment and a mandatory external-provider dependency.

A suitable existing option is [MapLibre GL JS](https://github.com/maplibre/maplibre-gl-js/blob/main/README.md?plain=1), licensed BSD-3-Clause. Nathaniel's `/home/nathaniel/code/OpenGeo/package.json` already lists MapLibre and PMTiles plus proof scripts. OpenGeo declares AGPL-3.0-or-later, so examine its approach and licensing before copying code. Do not replace OpenPlan or build a tile engine. An open renderer still needs licensed, attributed, available tiles; a provider adapter alone does not establish offline operation.

Priority: High v1 and adoption barrier. Correct the assurances promptly after safe handoff; build and prove the free reference path as a substantive milestone.

### E2. Local installation does not mean no data leaves the computer

Evidence: `README.md:80` says data stays on the computer and nothing is sent anywhere. `src/components/workspace-gis/layer-placement-preview.tsx:57-83` serializes an imported file's bounding polygon into an external Mapbox Static Images URL, and the component renders that URL as an image. This reveals the file's extent before the import is stored. It does not transmit the entire file or every feature. Other map and geographic source requests also contact external services. Optional cloud AI adds another explicit data boundary.

This is a code-supported contradiction in a privacy claim. I did not capture network traffic or establish an observed disclosure of confidential data. It matters to tribal cultural locations, proposed acquisitions, confidential alternatives, and community input. Existing engagement export privacy filtering and public-plan exclusions are valuable, but do not cover this outbound preview.

Fix the disclosure immediately and supply an agency-controlled external-service policy, including a genuine local cartography mode. Prove the closed mode with a deny-by-default network test: import a distinctive test extent and generate maps/artifacts while external destinations are blocked. Never treat a blank map as a successful private map workflow.

Priority: High accuracy-of-privacy-claim issue; confirmed code path, unperformed live reproduction.

### E3. Independent worker heartbeat is disconnected from model-run reaping

Evidence: `src/lib/models/run-liveness.ts` declares a 45-minute running-stage silence threshold. `run-reconcile.ts` probes fresh `model_run_stages.updated_at`, and `run-reaper.ts` calls `reap_model_run_if_stale`. The sole defining migration, `20260722000004_reap_model_run_rpc.sql`, checks run and stage timestamps, not `modeling_worker_heartbeats`.

Meanwhile `workers/activitysim_worker/worker_heartbeat.py` emits an independent heartbeat every 30 seconds with current run/stage identity. `supabase_poll.py:471-507` calls the complete behavioral pipeline between stage log updates. A long silent computation can therefore have a fresh independent heartbeat and stale stage timestamps. The inspected reaper classifies that condition as failure. This is a concrete lifecycle mismatch with the hours-to-days v1 contract. It is not evidence that today's short example run has failed this way.

Further, ActivitySim's `sb_patch_stage`, `sb_patch_run`, `sb_post_kpi`, and `sb_post_artifact` do not inspect HTTP failure responses. Final status patches are scoped only by row id. A late process can write after the reaper changes lifecycle state, and an unsuccessful evidence write can be narrated as written. I have not reproduced those fault paths. The worker also removes the existing per-run working directory before rerunning; this general polling path is retry-oriented, and should not inherit claims from the county worker's stronger attempt custody.

Repair through attempt-bound ownership/fencing, checked durable writes, and recovery tied to the correct worker/run. A heartbeat proves process liveness, not scientific progress, so do not replace this with an immortal-run rule. Lost contact should be explicit uncertainty with human recovery, not a fabricated crash. Prove healthy silent work, process death, database outage, restart, cancellation, duplicate claims, and late writes. Keep completed stage artifacts and exact input identity.

Priority: High for long or consequential model operation. Reproduce safely after the current acceptance workflow releases the tree.

### E4. A green QA gate does not cover the whole product

`.github/workflows/ci.yml` executes AequilibraE worker tests and modeling script tests, with one declared engine-import exclusion. It does not execute ActivitySim, county-onramp, OCR, or ODM worker suites. `scripts/ops/test-workers.mjs` discovers them recursively but explicitly stays outside `qa:gate`. `every-worker-suite-can-actually-run.test.ts` only imports suites when their local virtualenv exists and skips otherwise; clean CI does not provision those worker environments. Syntax/import coverage is not executed behavior.

`rls-gate.mjs` returns success if local Supabase is absent. Separate RLS CI does start a real stack, which is good separation, but a release assertion must join all required results on the same commit. I did not inspect remote branch requirements. Browser smokes run nightly/manual, not on pull requests, and intentionally omit workspace URL isolation. `upgrade-path.yml` runs on migration pushes/nightly, seeds nonempty records, and checks representative names/hash metadata; it does not establish complete record contents, all newer immutable packages, actual storage bytes, or the full workflow after upgrade. Restore has a separate script/workflow and should retain that distinction.

The direction checker enforces status vocabulary, required dimension membership, freshness and v1 all-proven labels. Its inspected dimension loop does not require an evidence reference when a cell becomes proven, nor tie every capability-by-role-by-geography journey to a current artifact. Independent context count is metadata, not verified independence. Keep the guard, but describe its scope honestly and make evidence references validate as coverage matures.

Priority: High release-evidence integrity; not a claim all existing tests are vacuous. Add executable worker CI and one release manifest that refuses missing, skipped, stale, wrong-commit, or failed required evidence. Do not rerun all numerical science on every unrelated text edit; distinguish cheap per-change checks, scheduled full environment checks, and the mandatory release evidence set.

### E5. Security foundations are real; agency access and records governance remain shallow

Sampled strengths: known roles fail closed in the action matrix; default-deny table/sequence grants exist; restrictive database policies deny viewer and unknown-role writes; live RLS tests query actual catalog enforcement; shared server/client separation and scoped public-data builders exist; project evidence export checks public engagement state. I found no new proven cross-tenant exploit in this limited sample.

An old comment in `workspace-write-gate.ts` says all database write policies are role-blind and intentionally allows unknown legacy roles through its API floor. The later inspected SQL denies those roles. This is stale explanation and inconsistent layers, not evidence of a present database bypass. Service-role side effects need their own review because database denial cannot undo external work.

The product's role vocabulary is owner/admin/member/viewer, with a viewer described as reading everything. That is workspace isolation, not proof of case-level confidentiality or records-steward authority within a multi-department agency. Searches found specialized privacy exclusions and survey-draft retention but no general legal-hold, records-request, or retention-policy implementation. This is a scoped negative search, not absolute proof no relevant behavior exists. A real records officer's journey is needed to distinguish missing behavior from discoverability.

Do not bolt an elaborate access system onto every module speculatively. First prove a confidential case, an outside consultant handoff, an approved public derivative, and a records request while the authoritative originals remain protected.

## Answers to the ten protocol questions

1. **What makes the ultimate free planning operating system?** A planner can take a matter from intake through sourced analysis, alternatives, consultation, decision, funding and implementation, then retrieve the exact authoritative record years later. Another person can continue the work after a staff departure or a computer failure. All states/DC and every core planning practice remain in scope, California deepest, with scientifically defensible separate travel methods. Free operation and data control must survive the absence of a commercial account.

2. **Can every type of US planner do core work?** No. The matrix itself keeps environmental/resilience and development-review work unassessed. Templates exist for environmental review, climate/hazards, housing, zoning, transit and freight; these are useful starting structures, not complete technical or statutory workflows. Missing or shallow jobs to test include development application intake/completeness, parcel and policy applicability, interdepartmental review, conditions of approval, amendments/appeals and implementation compliance; environmental alternatives and mitigation commitments carried into delivery; climate/hazard baseline-to-action monitoring; transit service proposal through operations/capital decision; public comment-to-response-to-decision traceability; fiscal authorization through reimbursement/closeout; confidential/tribal data and public-records processing. Existing plan content nodes, project deliverables, milestones, engagement and evidence bundles are plausible homes. Do not declare them absent merely because there is no dedicated module.

3. **Does every state work in substance?** No. The current registry and packet say no state is proven, most are not assessed, and the readiness registry has only California/Oregon/Puerto Rico exemplars. National foundational datasets and honest unavailable states do not establish state legal rules, source completeness or the journey outcome. Expand jurisdiction adapters and applicability proof alongside each real job.

4. **Is California gold standard?** No. It has the deepest legal-plan descriptor, source support and examples. Its own descriptor warns that it does not complete environmental review or establish legal sufficiency. No reviewed evidence covers all county/place identities and metro, rural, mountain, coastal, border and tribal agency journeys plus installation/recovery/accessibility on one candidate. Preserve California as deepest proof environment without making it a default.

5. **Are both models scientifically validated for every use nationwide?** No. Current known issues and the frozen direction packet preserve unknown nationwide accuracy and inconclusive diagnoses. ActivitySim execution is real and must not be resurrected as wholly missing. Locally fitted population does not validate borrowed behavior. Separate AequilibraE and ActivitySim outputs, common evidence boundaries, multimodal coverage and use-specific untouched geographic tests remain necessary. E3 adds operational work that scientific execution needs; it does not replace scientific work or justify shorter runs.

6. **Simplest overlooked idea with largest effect?** Make the professional planning record portable and operable without the original computer, original operator or external map account. The first thin slice is a free private reference deployment plus independently restored, reopened and reused project/plan decision packet. This crosses every discipline and exposes integration failures that another module-specific guard misses.

7. **Which old rule or decision is wrong?** The unconditional free Docker Desktop/Vercel assurances and no-egress statement are wrong or unsupported for the promised audience. The stage-timestamp-only reaper predates independent heartbeat and full long ActivitySim execution. Excluding workers from the ordinary gate because they take minutes is tolerable only if mandatory complete release evidence runs elsewhere. The operating manual's blanket ban on all hardcoded geographic counts conflicts with deliberate country adapters/coverage registries; keep neutral core types, but explicit named jurisdictions in maintained adapter data and test coverage are necessary. None of this permits shrinking v1.

8. **Remove, join or deepen first?** Join operator health, worker claims, recovery and evidence status so one job has one truthful lifecycle. Join public/private derivative policy and outbound-service configuration. Deepen Projects/Plans/Document Library/My Work for real departmental handoff and records responsibility. Retain specialized engagement, grant and model functionality. Remove false assurances and redundant guards that only restate labels when a behavioral gate owns the obligation. Do not delete working capabilities or merge demand results.

9. **What would prove the recommendation wrong?** A current clean-machine agency installation using no paid entitlement and no required external map service; captured no-egress operation that still renders and exports maps; a greater-than-45-minute silent ActivitySim run with fresh independent heartbeat surviving both page reconciliation and cron without lifecycle corruption; enforced CI execution of all worker suites; and an independent complete planning case/restore/public-records journey on the same candidate would each refute the corresponding gap. A found existing case/records system with those behaviors would move work to wiring/proof rather than construction. A full-depth completed professional journey showing legal/source deficits dominate daily failures could change the ordering, while leaving the free/privacy/recovery fixes required.

10. **Highest-leverage next completed outcome?** After closing candidate acceptance safely, deliver an independently operated, free, private and recoverable agency planning case using the existing project/plan spine. Choose one real representative case and a second organization/geography to falsify single-context assumptions. Its public output and confidential originals must remain distinct; a second authorized person must reuse the evidence after restoring to a separate machine. It is one milestone toward full coverage, never a substitute for all states, core jobs or scientifically validated models.
