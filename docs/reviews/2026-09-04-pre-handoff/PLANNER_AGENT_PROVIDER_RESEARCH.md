# Planner Agent: user-selected API models and installed CLI backends

Research and proposed design, 2026-09-04. No provider integration has been implemented by this review. OpenPlan source inspected at `fa0fb1c9d783dba7c156a7ddf8e450a64ccf2aa3`; the active checkout remained read-only. Provider documentation is a dated compatibility finding, not a permanent entitlement guarantee.

## Product requirement and engineering decision

Nathaniel wants the existing Planner Agent to use a person's chosen API model or an installed, authenticated Claude Code, Codex or OpenCode backend, including the user's own subscription where supported. His explicit reference is [Theo's T3 Code](https://github.com/pingdotgg/t3code). This is an early product priority, not work to postpone until every planning module reaches v1.

Design an optional local connector and provider adapters around OpenPlan's existing context, proposal and approval system. The installed CLI remains the agent runtime and owns its provider login. OpenPlan owns case access, evidence meaning and consequential actions. Direct API access remains available. A remote OpenPlan server cannot discover or execute a CLI installed on a visitor's computer without a paired local component.

| Direct APIs and local model endpoints | AI SDK has native provider adapters and an OpenAI-compatible adapter, including custom endpoint/model configuration. One additional reuse candidate is [AI SDK's Codex harness adapter](https://github.com/vercel/ai/tree/main/packages/harness-codex). Its reviewed README installs the SDK/CLI inside a sandbox and identifies Vercel Sandbox as its currently supported sandbox choice. That is a different deployment premise from the installed-local-CLI requirement. Evaluate only if a supported free local path and the required auth/control behavior are demonstrated; do not migrate OpenPlan to SDK 7 or provision a hosted sandbox merely to use it. The ordinary API provider abstraction is already a closer fit.

## Boundaries to implement

1. **Connection belongs to a person and device.** Show API versus local CLI, provider/model, installation and sign-in status, and the computer that will execute the request. A workspace administrator may restrict which project data can leave through personal connections. A personal account must not become the backend for anonymous public submissions or other staff.
2. **Separate model choice from entitlement.** Discover available models, allow explicit compatible model IDs and expose unsupported features. Record requested and actual model/backend. An exhausted subscription stops or queues with an honest status; never silently switch to a billed API, another model or a different privacy policy. Usage/cost may be unknown or estimated; do not label it zero.
3. **Pair the browser to a local connector.** Use authenticated, revocable pairing bound to allowed origin and OpenPlan user/workspace. Protect loopback from hostile websites, DNS rebinding and arbitrary command execution. Desktop-local mode is the first supported topology; a remote browser or phone needs an explicitly paired executing computer and tested secure transport. No arbitrary shell command field belongs in provider setup.
4. **Give the agent only selected case context.** Reuse authorized context builders and bounded evidence reads. Deny unrequested host files, database service-role credentials, unrelated browser sessions and global hooks. Provider-native login stays local. A CLI with broad default tools needs a demonstrable restriction boundary before confidential cases can use it.
5. **One action system.** CLI tools reach OpenPlan's scoped reads/proposals through the same registry, using narrow, expiring agent credentials. Consequential changes still require the exact human-reviewed version/payload. Shell approval is not project publication approval. Do not expose a general database or unrestricted HTTP tool as a shortcut.
6. **Durable, bounded execution.** Connector runs outlive a single HTTP response, have attempt/session IDs, bounded logs and events, interruption acknowledgement, reconnect and explicit terminal states. Retrying a stream must not execute a proposal twice. Cancel only connector-owned work. Device offline, login expired and quota exhausted are different states.
7. **Portable evidence, controlled history.** Store sources, citations, backend/model, actual tool outcomes and human decisions with the case. Switching providers starts a disclosed context transfer under the workspace's policy; previous hidden reasoning or a runtime-specific session ID is not portable project evidence. Redact secrets and private originals from public exports.
8. **Separate foreground and unattended AI.** This priority enables a person's Planner Agent. Public moderation, translation, scheduled synthesis and worker tasks currently using Anthropic need their own deployment connection and operating policy. They cannot quietly consume whichever member last connected a subscription. Basic participation and ordinary planning work must remain usable without AI.

## First implementation and definition of done

After safe development handoff, scope an early A0 milestone around a planner reading a project and its selected evidence, drafting a cited response, then reviewing one existing typed proposal. Begin with direct API selection and one local backend, while keeping Codex, Claude Code and OpenCode as explicit completion requirements for the priority. Deliver each backend through the same capability contract; no provider is considered supported solely because a test prints a response.

Done means a person can install/configure a supported CLI from visible setup, see the right model and account mode, complete the same planning task through each required backend, stop/recover it, inspect citations and approve the exact allowed action. An unsupported model or missing CLI explains the next step. No API key is required for a verified supported subscription path. Ordinary non-agent work still functions.

Verify deterministic adapter/event fixtures plus real installed-runtime acceptance, separately. Cover malformed/truncated/reordered output, disconnect after a tool, stale approval, cross-workspace access, revoked pairing, hostile origin, prompt injection in a source, forbidden host-file reads, quota exhaustion and cancellation without duplicate writes. A harmless event/log addition must survive a changed guard's mutation test; bypassed approval, wrong backend/auth and completed-on-error mutations must fail. Real acceptance uses only explicitly permitted test content and no paid fallback.

Observe a student or solo planner and an agency planner completing a real task. Evaluate comprehension of what was sent, what changed, and which account was used. Agent simulation cannot establish whether the assistant makes sound planning work easier.

## Costs, risks and remaining decisions

OpenPlan adds no required subscription or paid infrastructure. Users supply any optional provider account they choose. Measure startup latency, RAM, context usage and local event storage. Subscription limits and provider interfaces will change; maintain a dated tested compatibility matrix and explicit support range. Installation and auth problems create real support work even when model usage is included in an existing plan.

Engineering owns adapter choice, protocol handling, packaging, pairing and tests. Nathaniel's product input should select representative planning tasks and agency data-sharing rules. His early-priority instruction resolves the old scheduling assumption: provider choice for proven Planner Agent tasks starts early; broad autonomous coverage expands only as each underlying workflow earns its evidence.
