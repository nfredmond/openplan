# Private original artifact preparation

Extend the retained Products and Inspection stages under existing M3/M5b.2.
Reuse their original bytes and metadata receipts. Prepare one ordered manifest
for a later transfer adapter, without creating another file store or callback
schema. The current four selected product kinds remain unchanged.

Bind installation, target, original dispatch, application job and actor, task,
observation, product receipt and inspection receipt/report. Each retained row
names a fixed relative file, actual byte count/hash and supported content type.
Absent selected products retain null size, hash and file. List mesh and preview
as unselected contract kinds; this is not a completeness or absence assessment.
Native inspection states remain separate from map placement and quality.

Keep the manifest and completion receipt private and immutable. Verify current
actor access before the manifest and again before completion. Check ownership,
cancellation and deadlines around publication. Replay checks the original
Products/Inspection stages and compares exact manifest bytes; an altered or
missing manifest cannot be inferred from its completion. Interrupted work keeps
its original manifest for recovery. No URL, expiry, token, upload, callback or
application status change belongs to this stage.

Validate source cases with harmless survivors and targeted faults. Use the
existing retained selected 409 database for useful original-file and current
actor checks, with its source inventory pinned separately from newer app main.
Preserve exact saved replay, an actual child exit after manifest publication and
post-manifest revocation. This does not establish a current installation,
complete restore, physical accuracy, recipient usefulness or full recovery.
