# Retained task outputs and complete result accounting

September 30, 2026. Unreleased internal development after [bounded segment tasks](TASKS.md). No model dispatch, job tables, routes or browser controls are enabled.

`openplan/src/lib/engagement/synthesis-generation-results.ts` serializes each result against an expected job, plan, task, attempt, configuration revision/hash, provider and model. It preserves the original output and provider metadata text, including whitespace, partial or absent output and unknown usage. Zero tokens remain distinct from unknown tokens. Contradictory outcomes, invalid counts and reversed timestamps are refused. Exact replay reproduces the same capture and checksum.

A configuration hash alone cannot distinguish saved revisions with identical settings. The binding therefore names the exact configuration revision as well. Provider metadata text must come from the adapter's selected safe receipt fields; it must not contain credential objects or authorization headers. Serialization does not prove that a provider actually produced the output, and it does not persist the capture.

Assembly starts from the independently verified source plan and the durable ledger's explicitly selected attempts. It refuses unknown or duplicate task selections, shared attempt IDs, unselected/duplicate receipts, changed configuration identity and older results substituted for a new attempt. It accounts for every planned task in stable order, preserving original receipts separately from parsed observations. Missing work remains unstarted or awaiting a result. Failed, interrupted, malformed, truncated and model-declared incomplete outputs remain distinct. A model's complete label cannot override an incomplete provider finish reason.

Every task must have a validated selected result before the stage becomes ready for record/context consolidation. This is not a completed synthesis or review approval. Empty contribution selections retain their source and context without requiring any model attempt; selecting an attempt for that empty set is refused. Interpretation remains unassessed.

## Verification and limits

The focused result suite passes 18 tests. Combined source/input/record/field/task/result tests pass 132 tests across eight files. Lint and TypeScript pass on restored source. [Check receipts](results-checks.json) retain source and log hashes. [Full QA and shuffled tests](protocol-checks.json) pass on the combined task/result increment with 16,022 tests passing and 828 explicit skips across 1,349 passing files. The shuffle seed is 650933. QA also passes configured lint/dead-code checks, provider connector tests, a zero-vulnerability dependency audit and the production build/typecheck. The opt-in live database gate is explicitly skipped; this increment changes no native writes or schema.

The [fault results](results-mutations.json) retain two passing controls and 33 caught targeted failures. They cover authority/attempt substitution, original output and provider metadata, unknown usage, chronology, schema, resource limits, missing/duplicate selections and receipts, capped inventories, false completion, provider finish reasons, lost originals and changed manifests. The [runner](prove-results.py) restores the implementation after each run.

The [first probe](results-first-probe.json) found a surviving unknown-task mutation. Its supposedly new attempt ID collided with an existing fixture attempt, allowing the duplicate-ID guard to mask the removed unknown-task guard. The fixture now uses an unused ID; the corrected probe catches the removed guard. The initial failure remains recorded. Another initial assertion about replacing an older attempt used the same colliding ID and was corrected before this probe run.

These are structural and preservation checks. They cannot establish provider authenticity, semantic quality, record/context consolidation, authentication, membership, cancellation, lease authority, durable storage or save recovery. Job identity and selected attempts must come from an authorized native ledger, not browser-supplied expected values. Older attempts remain separate retained history; this assembler takes the ledger's selected set and never chooses the newest output itself. Native jobs, worker custody, exact staff import and browser acceptance remain unfinished. Manual preparation/review stays available, and no M9b or V1 requirement is closed here.
