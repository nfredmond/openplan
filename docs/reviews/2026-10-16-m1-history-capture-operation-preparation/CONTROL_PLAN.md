No control helper, reader, runner, request, supplied fixture, operating authority or execution is authored. This plan targets the new caller/admission seams only. It replays none of22,19/6,9/12/5 or prior archive controls. Exact module identities/source locations and a strict outcome reader would need a later source-reviewed map before any finite PURE request.

The proposed count is16 supplied observations:14 caller invocations and two direct tiny chunk checks. These are ten caller behaviors plus one intact chunk behavior, followed by four caller mutants and one chunk mutant. Count is a proposal, not an executed population. The test branch would be an explicitly isolated SUPPLIED_BOUNDARY_AND_OWNED_REAL_FDS_ONLY definition, with a deliberate source-only entry substitution that can never serve as ROOT authority. No real process, signal, tool, dump or service enters it. Production admissionNone itself remains an intact refusal case. Every constructed reader/guard later needs its own harmless/targeted evidence before acceptance, with any resulting count amendment disposed before grant.

Pure overrides are explicitly supplied-only function globals, never arbitrary ROOT JSON authority or a real archive alias. Real saved OS delegates close every owned FD even when injected boundary failures raise after the real action. The final readback checks exact new source/variant-free bytes, modes/metadata and fixture bytes/metadata. No stdout history or arrays are decoded. One bad unexpected outcome stops with partial/raw evidence and no retry.

The combined case covers only declared finalization errors, not every allocation/formatting/partial-open/process-quiescence/storage combination. Primitive supplied callbacks do not prove an actual operating outer, real expiry authority, named RO mounts, namespaces, socket denial, resource enforcement, child lifecycle, serialization, SQL semantics or archive compatibility.
