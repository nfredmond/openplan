# Independent live extraction RLS and cancellation guard verification

The reviewed guards pass their live fixture assertions and fail when their intended protections are deliberately removed. The tests ran only against Docker container `supabase_db_openplan_owp_preparation`, whose inspected PostgreSQL5432 port maps exclusively to host56322. Container identity was asserted before database work and again before the added document-scope cases. The recorded identity is in `container-identity.json`.

## Method and safety boundary

The actual `work-program-recovery-rls.test.ts` was snapshotted and transpiled with its subprocess call intercepted. This captured the exact SQL generated by its two relevant cases: extraction-version isolation/direct-write refusal, and cancellation. The other five test cases were captured but not executed by this review. The captured SQL and source hash are retained here.

Each live execution starts BEGIN, applies any mutation inside that transaction, inserts its synthetic fixtures, runs the original assertions, and ends ROLLBACK. No COMMIT was issued. An intended assertion failure causes ON_ERROR_STOP to close the psql connection, rolling back that transaction. Local3-second lock and15-second statement limits prevent prolonged lock contention. No existing service was stopped or restarted, no other database was used, and no repository source was edited.

## Extraction policies and privileges

The baseline and harmless-comment control both reach the success sentinel. The fixture creates one `kb_document_extractions` row and one `program_work_program_extractions` row and verifies:

- A workspace viewer can read both.
- An outsider cannot read either.
- Authenticated direct updates to either retained table are denied.
- An authenticated caller cannot invoke the service-only enqueue RPC while supplying another actor's identity.

Five independent transaction-local mutations each fail the intended assertion: opening either table's SELECT policy reports `Foreign pages visible`; granting/updating either table with a permissive UPDATE policy reports the corresponding direct-edit sentinel; granting authenticated execution on the actor-accepting enqueue RPC reports `Actor spoof allowed`.

## Cancellation predicates

The baseline and harmless-comment control both pass the actual seventh test. It verifies owner/member access, owner retry, viewer/outsider/revoked-member rejection, job ID, active status, extraction job kind, and unchanged original checksum.

Six separate replacement-function mutations fail at their corresponding assertion: viewer admitted, outsider admitted, revoked member admitted, missing job-ID predicate, terminal status admitted, and export job kind admitted. The revoked case specifically verifies access denial before considering the terminal/job-kind result; it does not rely on a successful data mutation after revocation.

An additional independent fixture creates a second document and its extraction job in the same workspace. Cancelling that job while supplying the first document ID is refused. Baseline/no-op pass, and removing the document-ID predicate reports `Foreign-document job cancelled`. This extends beyond the repository test's nonexistent-random-job check.

## Restoration and evidence

There were18 rollback-only transactions: six passing baseline/no-op runs and12 intentional failing mutations. `results.json` and `scope-results.json` record the exact expected failures. The function definition and policies matched their pre-test values after rollback. `final-restoration.json` confirms the function remains unchanged; all synthetic users/documents/workspaces from the final scope fixture are absent; authenticated UPDATE rights on both retained tables and authenticated EXECUTE rights on the enqueue RPC are all false. The primary fixture user IDs were also checked absent after its runs.

Git status was recorded before/after shell work; root was editing concurrently, so unrelated differences are not attributed to this reviewer. Every probe/source snapshot/report file was written under this explicit scratch directory.

## Blind categories

This is live PostgreSQL policy/function evidence using SET LOCAL ROLE authenticated and synthetic JWT subject settings. It does not test HTTP authentication, route payload authorization, browser reachability, real storage object bytes, or worker interruption/acknowledgement behavior. The cancellation fixture proves that the stored original checksum is preserved, not that independently downloaded bytes match it. Actual source extraction quality and generated document usability belong to the separate source/artifact reviews.
