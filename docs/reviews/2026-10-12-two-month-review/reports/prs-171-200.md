## #195: the 19 machine-translated catalogs

What holds up:
- Each catalog has all 259 keys, no empty values and matching placeholders.
- Each file is labelled as unreviewed, and pages show a "Machine translation" label in that language.
- Diné Bizaad is deliberately left out.
- Spot checks of Somali, Hmong, Khmer, Tagalog and Amharic carry the meaning of the protected sentences. I can't judge fluency.
- The review note names where fluent reviewers should start.

Problems:
- **Translations go stale silently.** Catalogs are matched to English by message key only. When an English string changes, all 19 translations keep the old meaning and no test fails. That includes protected caveats, and the next copy cut will trigger it.
- **Script subtags are dropped.** `normalizePortalLocaleTag` (`locales.ts` line 196) keeps only the primary language code. Traditional Chinese readers (`zh-Hant`, `zh-TW`) get the Simplified catalog without notice, which matters for California agencies. Punjabi in Arabic script (`pa-Arab`) gets Gurmukhi.
- **Provenance is thin.** "Four agents" is the whole record of who translated.
- **The CHANGELOG overstates coverage.** Demographic options and survey widgets stay in English, and it names the wrong setting: it says `PORTAL_MACHINE_TRANSLATED_LOCALES`, but operators must edit `CATALOGS_WITHOUT_MACHINE_NOTICE`.
- **No usable browser evidence.** The check names three views but records no build or captures.
- **Text is multiplied.** Every heavy English string now exists 21 times, so cutting text is 21 times the work.

## #196: does public engagement work without a Mapbox key?

Yes for `/engage/<token>` and `/embed/<token>`:
- **Engine choice:** `public-map-stage.tsx` lines 65 to 69 pick Mapbox when a key exists, MapLibre when the style variable is set, otherwise no map.
- **Safe fallback:** the server's decision (`portal-surface-props.ts` line 174) is combined with the client's, so a mismatch shows the honest "map unavailable" notice, not a blank map.
- **Content-security policy:** it adds the style's host and allows the blob workers MapLibre needs.
- **Docs:** `SELF_HOSTING.md` says to rebuild after setting the variable. A Docker operator who sets it only at runtime gets the notice, not a map.
- **Evidence:** browser checks covered a local Protomaps extract and OpenFreeMap at desktop and 390 px.

Gaps:
- A MapLibre construction failure, such as no WebGL2, is not caught (lines 806 to 818). The resident gets a broken map instead of the notice.
- Place search and the background picker disappear.
- Staff views, Explore, Corridor Analysis and the geometry picker outside the map stage still need a key.
- No tile extract ships with the repo.

## Synthesis

**Themes.**
- **Recovery and custody dominate by volume.** Evidence under `docs/reviews/` grew from 4,896 files (105.9 MB) to 5,759 files (124.3 MB).
- **A real user-facing push.** The dashboard, map frame, words pass, light mode, engagement map, room limits, 19 languages, keyless map and Maps all landed in about 14 hours.
- **Public hosting went live,** with spending caps but thin abuse protection.

**User-visible versus internal.** About 15 PRs visible to 13 internal. By added lines it is roughly 1 to 6. The user-visible work came almost entirely from the Claude Code lanes, and the internal work from the Codex lanes.

**Recurring quality problems.**
1. **Bot findings merge unaddressed.** At least six P1s remain on main, across #187, #193, #194 and #189.
2. **Written holds don't stop merges.** #190, #197, #199 and #200 went through, and your memory notes the same thing happened at #204.
3. **Two writing standards in one app.** The Codex lanes write receipt-and-custody prose into the UI, and into PR bodies you can't realistically read ("frozen bf1/W4", "exact 6a", "f72"). That matters because you are the only possible human reviewer.
4. **Code that only works for some places.** The vendored map skill knows only US states and Puerto Rico. The locale resolver drops script tags.
5. **Abuse resistance traded for access without a recorded decision.** This covers the #194 device tokens and open public signup on a capped budget.

**Recurring documentation problems.**
1. No CHANGELOG entry for the UI overhaul.
2. Statements go stale within the day.
3. Review findings never reach KNOWN_ISSUES.
4. New capabilities get no roadmap milestone or ledger row.

**Observations for replanning.**
1. **Fix the open P1s first.** In order of harm to planners: vote inflation on the public site (#194), missed dates absent from the dashboard (#187), the light-mode result card (#193, after a browser check), and the two map-package checks (#189, needs a new migration). Log each in KNOWN_ISSUES until fixed. This is hours, not a lane.
2. **Make holds mechanical.** Use a required check that fails while a hold names the branch, or require one approval on main. Add a minimum open time so the Codex review can post and be answered.
3. **Run one words pass across every lane, starting with `managed-gtfs-imports.tsx`,** then the synthesis panels and the engagement staff pages. Widen the build-notes guard to the custody vocabulary: "receipt," "custody," "operator-facing," "apply the latest migrations." Require plain PR bodies.
4. **Rebalance hours toward planner work.** Recovery now has same-host, separate-cluster and coordinated-point proofs. Consider pausing new recovery evidence until M9 engagement or M2 casework gets its next increment.
5. **Close the hosted abuse gaps before inviting anyone.** Add a signup bot check, per-account quotas, and a Mapbox usage cap or URL-restricted token. Decide whether OpenPlan mail should go out from the Nat Ford domain. Then update ROADMAP M15, `AGENTS.md` and the CHANGELOG.
