# Explicit original aerial task command

The candidate adds `--fetch-original` to the existing task metadata command.
File recording and saved-digest reads remain separate modes. An original fetch
requires the retained plan, separate private metadata root, explicit trusted
native daemon socket/UID and a private credential file bound to the original
reference. The supported native attestor surrounds one owned GET. There is no
implicit network poll, engine write, processing commit, callback or publication.

SIGINT and SIGTERM end command ownership. A refused or interrupted command exits
two and prints no success summary. Existing durable records remain available for
inspection. Token bytes stay off the command line and bounded summary. Keep the
credential file in the installation's protected configuration inventory.
[Operator instructions](../../../workers/odm_worker/TASK_METADATA.md) describe the
supported native profile and explicit inputs.

## Limits and continuation

The loopback signal test supplies a synthetic engine-check adapter; it tests the
actual GET and command lifetime, not native engine identity. The separate native
command uses the real supported attestor. It sends three deliberately invalid
ordinary inputs in its inherited producer and retains the reported failed state.
It cannot establish image decoding, scientific quality or successful processing.
The producer reuses an older retained internal fixture network, not a current-main
or hosted database. Failed and unsupported remain distinct from zero.

Saved metadata retains its unassessed claims and denied publication permission.
The command does not establish later freshness, current application actor access,
original-task effect reconciliation, results/callback custody, full worker or
installation recovery, long computation, clean commissioning or physical-host
acceptance. No schema, default activation, hosted setting or release tag changes.
Full M3 and v1 remain open.
