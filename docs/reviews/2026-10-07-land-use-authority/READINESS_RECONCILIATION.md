## Readiness behavior

An older draft can retain nonempty applicable keys while omitting a newly
required key. The previous shared progress function treated that saved list as
complete. The freeze route also tested only saved keys. The workbench separately
added every nonconditional rule, including unselected locally defined sections.
These checks disagreed with each other and with the native transaction.

The shared function now returns the distinct union of saved keys and every
descriptor-required key. Readiness and progress use it. Both the mounted
workbench and freeze route supply their actual descriptor. Saved conditional,
local or historical keys remain binding until explicitly reconciled. Unselected
conditional or locally defined keys are not silently added. Creating a new plan
still uses its existing default applicability selection.

The native freeze transaction already uses this required-key union in migration
`20261016000004`. This change reuses that protection and adds no migration. It
does not revise a saved checklist, delete old content or substitute new rules
for a frozen version. Frozen workbench custody and explicit older-draft
reconciliation remain necessary before connecting the new selector.
