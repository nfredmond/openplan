No `ready`, `source_pins`, `raw`, `read`, JSON parser, descriptor, private-path verifier, ACK verifier or correlation function receives a stub. The new source loader temporarily installs only these three parent modules. It executes their original function globals through module-local I/O adapters. All accepted runtime files and the original generic collector remain data only.

The 33-file read allowlist comes from the first handoff's exact reviewed operation footprint. The fixture independently constructs its expected source ledger from that list. Production `required_source_files` still checks the ledger's exact membership. Popen expectations use literal manager argv and environment definitions in the adapter, rather than the production argv variable itself. Accepted source input bytes and retained actual18 oracles remain pinned external data.

The 28 chosen mutant anchors occur once each in production source. Mutation happens only in a per-construction TEST source overlay. Tests never edit production files. The loader reads the overlay and presents the same lexical `__file__` and production paths. This lets the actual source pin and root-intent joins cover the selected overlay without rebinding ROOT or SUBJECT to scratch strings.

Each construction records import intent before loading the parent. It retains an outcome, supplied process events, raw file/pipe capture and restoration metadata. Final restoration closes all owned descriptors independently and restores source overlays to initial bytes and modes. It restores prior module dictionaries and `sys.modules` entries even if descriptor cleanup raises. Unexpected close errors remain errors; the adapter does not silently mark failed closes complete.

Static inspection alone found three draft control conflicts before sealing. The readiness type/off cases now co-seal saved `ready.stdout` with the altered readiness JSON, so their intended identity gate is reachable. The partial-open close oracle selects the output stream by its supplied `kind`, excluding later evidence-reader streams with the same filename. The terminal-record failure case separately checks the captured process status and `terminalRecorded=false`. A failed terminal record does not rewrite the already constructed process row into a different classification. The actual parent refuses the false durability join. No execution or observed failure produced these source corrections. None changes a production function, assertion label, old packet or receipt.

The model's supplied PIDs and invocation are counterfactual identifiers. They do not represent a future TEST unit or the owned native unit. Fifty-one constructions write seven fresh synthetic child journals each. Eight additional collector-only constructions use fake Popen without native journal models. All 59 fake Popen calls retain real FD behavior. Other constructions stop before Popen or call direct functions. There are zero real child dispatches.

Blind categories remain explicit. Coherent simultaneous corruption of both a fixture and its independent literal expectation can evade a model. Accepted external data pins establish source custody, not new installed truth. These controls cannot establish PostgreSQL parsing, live manager grammar, target state, source closure, physical restore equivalence, backend death, hostwide confinement or arbitrary failure durability. A source assertion failure establishes none of those native tiers.
