## The reporting grammar is a fixed current-format contract

Require exactly one entire header:

```text
Running as unit: <exactUNIT>.service
```

The only optional suffix is exactly `; invocation ID: <nonzero32lowerhex>`.
There are no leading/trailing characters. Require exactly one of each whole
success line, with ten ASCII spaces before Finished and none before Main:

```text
          Finished with result: success
Main processes terminated with: code=exited, status=0/SUCCESS
```

Every line is classified. Normalized start/result/main markers catch malformed
variants, foreign/extra headers, mixed markers and duplicates. A line that fails
the expected-unit regex is not ignored. The only other allowed lines are ASCII
space-indented Service runtime, CPU time consumed and Memory peak reports.
These resource reports are explicitly unbound, not actual cap/INV authority.
Unknown lines, carriage returns, non-ASCII, blank inserted lines or missing final
LF refuse. This narrower current-format choice is exposed for root review;
no universal systemd-version support or real future output is claimed.

Absent suffix is recorded null/false. A present suffix must match independent
ACK001. No invocation is fabricated or adopted from defaults/post-show.

## New collection failure state is explicit

The new collector returns `{terminal,terminalRecorded,terminalRecordError}`.
Persisted terminal keeps the original fields plus cleanupErrors/evidenceErrors.
A clean logical terminal requires code0, primary null, both error lists empty
and classification terminal-zero. These overlapping conditions are one guard,
not independently claimed mutation kills. Primary+cleanup, cleanup-only, partial
setup, uncertain evidence or terminal-record failure refuses. A null hash/length
denotes unavailable evidence, not an empty stream or fabricated digest.

for an absent/uncertain terminal. Parent keeps local primary and collection data
if its own record fails, attempts failure custody before unlocking and reports
record failure explicitly. Full physical durability or survival under OOM/host
death is not established by source or a future finite supplied control.
