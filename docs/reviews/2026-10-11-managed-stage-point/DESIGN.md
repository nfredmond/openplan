# Managed admission and progress recovery point

This continues M3 from the coordinated known-root proof. It will retain native
managed claim and progress commands, their execution-admission rows and an
attempt-owned workspace in a full encrypted database/file point. It must recover
original uncertain receipts without admitting another callback. No scientific
engine or protected study runs. No worker contract, migration or hosted wiring
changes occur.

## Required sequence

1. Restore the unchanged prior encrypted point into the new source and compare
   all table images, sequences, schema catalogs, roles, properties, key and files.
2. Create separately labeled synthetic queued runs/stages. Exercise an actual
   native claim whose reply is dropped after commit. Its execution admission
   must remain unconsumed and its callback count must remain zero.
3. Exercise a separate fresh claim with a checked receipt and current ownership
   read. The admitted callback creates an actual attempt workspace and synthetic
   input/output bytes. The bound writer sends a progress command whose committed
   reply is dropped. It stops with the original unresolved request; later writes
   are refused. Retain the consumed execution admission and owner marker.
4. Verify the expected native write graph against all original rows. Preserve
   unexpected changes as failed trials. Stop the exact owned API and establish
   the known fixture's database/journal quiescent interval.
5. Snapshot every populated journal with the installed operator. Inventory the
   entire known root, including admission records, owner marker, inputs, outputs,
   empty directories and modes. Capture the full native database, role/config
   and key records with unchanged retained transit files in the same interval.
6. Encrypt, fully read-check and restore into separate private storage. Restore
   the target database into its separate cluster and volume. Verify native images
   and complete file/logical-journal equality before receipt recovery.
7. Fresh installed CLI processes recover each original uncertain command using
   its saved logical origin and installation. Compare exact request/response
   bytes and independent server request/receipt/attempt/stage/parent records.
   Repeated cached receipts send no additional request. Neither recovery admits
   another callback or reconstructs a running writer.
8. Inspect the retained claim's current native ownership through the installed
   CLI. Its answer remains point-in-time only, with continuation unauthorized.
   Rollback-only changed-parent/attempt controls must reject an old ownership
   inference. They are query-projection controls, not a real replacement lease.
9. Compare every final native image, role/property/key record and permitted local
   journal change. Verify original point preservation. Stop only the exact new
   services and retain all resources, sources, results and failed trials.

## Failure controls and limits

Exercise missing native claim/progress receipts, wrong installation, removed
execution admissions, changed owner markers, lost WAL records, missing files
or directories and altered schema policy/default privileges. Each new guard
needs a surviving harmless control and a targeted broken behavior that fails
its intended assertion. Restore mutations in `finally`; native mutations use
rollback-only transactions. Record the blind category of each check.

This is a synthetic admitted-stage custody join on one physical host/disk. It
does not resume engines, connect normal polling, prove every worker family,
validate useful computation beyond 45 minutes, establish a general writer fence,
recover from physical-host loss or commission a clean agency installation.
No browser, practitioner, scientific, historical Vault or hosted acceptance is
established. Keep all M3 and V1 requirements on the active roadmap. The relaunch
agent retains hosted coordination and the main merge hold.
