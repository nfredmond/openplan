# Original URL inputs advance one draft command

The explicit candidate pipeline composes owned admission, frozen original URL
intake/preparation and the existing one-command draft bridge. Its preparation
adapter reads original saved settings and source mapping. It does not call the
mutable supplier or fetch another URL. The [design](DESIGN.md) preserves separate
live authority and full worker recovery boundaries.

One advance completes or verifies intake, then issues at most one original init
or image upload. The original intent precedes transport and the checked exact
reply precedes the next command. A supplied authorization adapter must return
exactly `True` for the original plan and command. Uncertain prefixes hold without
another permission or request. Completed drafts hold processing commit.

Fresh bounded stage adapters share the pipeline deadline without mutating the
original intake timeout. The source clone reads the current cancellation callback.
Owner/cancellation/deadline checks surround saved input validation, authorization,
transport and final return. Supplied transports must carry the same actual caller
signal. Cancellation after an external request preserves its unresolved intent;
it does not infer failure or permit reissue.

The default/deployed pipeline, application routes, public schemas, migrations and
hosted configuration stay unchanged. Supplied application context and permission
remain unassessed live facts. The candidate issues original drafts, without
processing, terminal callbacks or publication.
