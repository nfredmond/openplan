# Freeze supplied preparation settings before source intake

Continue M3 and M5b.2 above supervised URL transport. Compose original owned
admission, retained URL sources and existing preparation as an explicit pipeline
candidate. Leave the default and deployed worker pipeline unchanged.

Validate and privately publish one original settings plan before the first URL
fetch. Bind request, admission, start, original supplied application projection,
installation and target, plus original engine identity, options, filenames and
byte/ZIP limits. Do not save source-root absolute paths in that settings plan.
Keep the source root separate and explicitly supplied on restoration.

Recovery reads and validates the saved settings instead of calling a changed
supplier. Source completion uses original slot receipts; existing preparation
consumes their exact paths and keeps its original task. A missing plan with other
records, including partial sources in the separate root, refuses. Save an immutable
source mapping before preparation. Bind that mapping to the settings plan and
reconstruct the expected source-plan hash from the original request, context and
limits. Check exact slot paths, sizes, hashes and declarations.

After mapping, recover from verified preparation slots or their original source
objects. Completed local preparation can replay with its separate download root
unavailable. Missing mapped bytes hold without fetching a changed URL. Missing
mapping after preparation or a missing source installation before mapping also
holds. Create the source installation seal before publishing settings, so an
existing settings plan cannot treat a lost source installation as first use.

Check the shared deadline and caller cancellation before intake,
during delivered writes and between preparation stages. Existing local preparation
does not gain interruption of arbitrary filesystem stalls. Original identity
remains unchanged, starts stay held, and neither completion nor recovery grants
engine permission or sends a callback.

Supplied application fields and engine identity remain unassessed live facts.
The injected fetcher needs the already proved supervised transport and its actual
cancellation signal. This pipeline does not establish live authority, deployment,
scientific validity, image decoding, complete worker recovery or browser use.
Prove changed supplier/settings, partial intake, original task/configuration,
actual owned queue operation and two-root restored copies, with harmless and
targeted broken controls. Main merges stay held.
