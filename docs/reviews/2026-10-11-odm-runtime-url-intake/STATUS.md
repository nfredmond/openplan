# Original aerial settings and source bytes survive interruption

The candidate pipeline freezes the supplied original preparation settings before
the first URL fetch. Owned admission, retained URL intake and existing preparation
now work together. Recovery reads the saved application projection, actor, target,
engine identity, options, filenames and byte/ZIP limits. It does not call a changed
supplier. The [design](DESIGN.md) keeps live authority unassessed.

An immutable source mapping precedes preparation. Its settings hash and rebuilt
source-plan hash bind the original request, admission, start and application
context. Slot validation checks exact order, private object paths, sizes, hashes,
original declarations and total bytes. Independent reads confirm the complete
source manifest and mapped bytes before preparation. Original task identity stays
with the existing preparation journal.

Recovery first verifies already retained preparation slots, then original mapped
source objects where needed. Completed preparation can replay with its separate
download root unavailable. Missing mapped bytes hold without refetch. Missing
settings with partial source records, missing mapping after preparation and a
missing source installation before mapping also hold. The source installation
seal precedes the settings plan, while settings still precede every fetch.

The pipeline checks its shared deadline and exact boolean cancellation at intake,
delivered writes and stage boundaries. It clamps the nested fetch deadline.
Existing local preparation does not gain cancellation of arbitrary filesystem
stalls or every local copy chunk. The supplied supervised transport still needs
the actual caller cancellation signal. Starts remain held; preparation grants no
engine permission and sends no callback.
