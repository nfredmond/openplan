## Queue behavior

Requests retain the exact actor/campaign/workspace, selected fields, raw source/version snapshots, locale, encrypted credential and selected workspace-key ciphertext hash. Exact client-intent retries return the original request before resealing credentials or rechecking changed source words. A changed intent under that id refuses. A whole batch creates together or rolls back. The canonical per-field packets and synthetic encrypted credentials used by the probes are produced by the actual application helpers in `generation-queue-fixture.ts`.

Each field moves from queued to a single reserved attempt, then to authorized dispatch. Claiming rechecks staff membership, source/translation version and selected key. Dispatch authorization rechecks them again. Quota reservations and usage events are distinct: queued/reserved fields have no dispatch event; authorization records one conservative event whose metadata says `dispatchReservation`. This proves authorization, not receipt by the provider or a charge. Exact authorization acknowledgement retries do not add events.

A second atomic allowance check at dispatch closes a gap found during implementation: another staff AI task may consume capacity while a translation waits in reserved state. The new path refuses an over-cap dispatch and leaves it unspent. It shares the existing API-worker advisory key and staff bucket list, including content translation; public translation events remain outside that allowance. Legacy producers which do not reserve atomically can still race their own metering. This is not a claim that all historical AI spend paths are globally atomic.

Request and field identity are retained. Reserved/started attempts are never reclaimed or requeued; expiry is terminal. Worker failures can be recorded before a claim without inventing an attempted generation or usage event. Minimal worker status detects lost scope, changed source/key and expiry. A terminal failure has exact replay semantics. Private requests, credentials and source packets have no browser table privileges or permissive RLS policies; only service-authorized commands write them. These SQL functions trust the server to pass the actual authenticated actor. A route must prove that binding before activation.

## Errors and limits

Preparation initially guessed two nonexistent filenames; the actual files were found with the repository inventory. An initial lookup tried the proof database on the wrong test container and was refused; the retained database is on `2731143`, not `2026091050`.

Three probe failures are retained. The first tried to demote the only workspace owner; the corrected fixture keeps a second owner during that test. The second combined an expiry mutation and a read in one assertion and observed the earlier state; separating them into successive statements fixed the observation. The third expected six minimal status fields when the intended result has five; the assertion now compares the complete expected object rather than a hand-counted field count. These were probe defects, not shipped application defects. Initial logs are hashed in `generation-queue-evidence.json`.

Expired reservations and quota saturation in the serial probe use explicit seeded states/events; that probe does not wait through a live 180-second worker lease. Source change versus claim is serially checked. Overlapping source changes, credential replacement, membership loss and quota contention across different campaigns still need live concurrency coverage. No successful output delivery, public generation queue, browser recovery, full feature QA/shuffle/RLS/worker/upgrade/restore gate or release is claimed.

## Continue here

1. Add retained completion/failure delivery and the local worker using the existing connector lock/private journal utilities. Reuse the captured generation adapter. The queue currently has no completed-output API or active worker. Record a separate immutable per-attempt output so late delivery can retain evidence without rewriting a cancelled/interrupted terminal job. Only a current eligible completed result may be published.
2. Preserve incomplete raw output too. The adapter can return NUL-containing or malformed-Unicode strings as incomplete evidence. PostgreSQL JSONB cannot store every such string. Retaining the exact JSON-serialized output as TEXT plus its own digest is a candidate for this join; do not silently replace those bytes or pretend that an unparseable result was complete. Decide and test the actual encoding before implementing delivery. Provider receipt fields need equivalent preservation/validation.
3. Connect strict credential preparation to the queue's selected ciphertext hash. The current application helper does not yet return that hash. The worker must verify encryption/key availability before claiming and must recheck the selected environment key across restart; PostgreSQL cannot inspect a process environment. Never silently refresh the saved encrypted envelope.
