# Original aerial engine effects remain durable

The disconnected engine journal freezes original source, admission/context,
engine instance/API/image/configuration identity, credential reference, settings,
task UUID and ordered upload filenames. It records each initialization, individual
upload or commit intent before returning its first-issue flag. An existing intent
returns false, including after an unresolved reply or interrupted acknowledgment.
No deployed worker, public contract, engine default, schema or scientific result
changes. M3/M5b.2 remain open.

The UUID check also matches the pinned API's version 1 through 7 and variant 8
through b restrictions. Nil UUIDs and other combinations refuse before an intent.
[Exact cached installed-source comparison](evidence/task-uuid-source-binding.json)
matches the prior retained digest. The new test subcases and targeted guard
mutation pass; no native invalid-UUID API trial runs. The corrected source gets
a new complete control/restore execution before publication.

[The design](DESIGN.md) follows the actual [NodeODM draft retry counterexample](../2026-10-11-odm-draft-reconciliation/STATUS.md).
The library reuses the private admission and retained-source mechanisms. It
rechecks actual retained bytes before each operation, rather than accepting a
caller-supplied custody boolean. Immutable plan and command hashes are independent
of filesystem location. Fixed journal names do not use source filenames as paths.
Cooperative private locks prevent two local callers from receiving a first flag.

The first candidate supports retained photo-manifest slots. ZIP derived-image
custody is explicitly unsupported here; the existing raw ZIP source candidate
remains available. File extensions do not establish image decoding or permitted
use. Commands are exact semantic descriptors with form/options or multipart source
slot, byte/hash and filename. No multipart wire encoding or transport runs.

## Replies retain their exact bytes

Checked replies retain raw body bytes, size/hash, status and parsed JSON. Initialization
must return the original UUID. Upload/commit acknowledgment requires `success: true`.
Duplicate JSON keys, nonfinite values, wrong types and bodies over 1 MiB refuse.
Different raw spelling cannot overwrite the original reply, even if parsed values
are equal. Malformed or unsuccessful replies leave the intent unresolved.

`engineCustodyVerification` stays `unassessed` for every acknowledgment. The first
flag records a local intent, not live authority, sequence readiness or permission
to process. Task absence does not authorize another effect. This library makes no
HTTP call and remains disconnected from the deployed worker and client.
