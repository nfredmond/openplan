## 1. What would make this the ultimate free planning operating system?

A planner should be able to carry an actual planning question through evidence collection, analysis, public review, accountable decision, implementation, and retained records without rebuilding the job at each stage. The same geography, source limits, exact artifacts, responsibilities, and human decisions must survive those transitions. A small agency must install and recover the product without Nathaniel, and a regional agency must reuse one evidence record across several projects without changing its meaning.

The v1 contract already describes this destination well. Keep its full US scope, California depth, distinct validated demand methods, and route to international adapters. Do not use release count or runtime to narrow it. The missing work is completion evidence across real combinations of planner, organization, place, and job. A long feature list does not answer whether a planning department can finish its work.

## 6. What simple overlooked idea has the largest product effect?

Use one canonical answer to “which projects does this evidence cover?” wherever it is displayed, exported or approved. Preserve the human-reviewed public response with that evidence.

The source contains a specific inconsistency. `openplan/src/lib/engagement/campaign-projects.ts` loads campaigns covering a project through both the lead-project column and the full join table. `openplan/src/lib/project-evidence-bundles/generated-records.ts`, at the campaign read around line 271, filters only `.eq("project_id", project.id)`. That list supplies publishable engagement geometry in the generated GeoPackage. A campaign covering project B while leading project A can therefore appear on B's project page and be absent from B's generated engagement geometry. The code-level selection difference is established; the visible end-to-end omission still needs a browser and downloaded-artifact reproducer.

A second source defect is direct. `loadCloseLoopEntries` in `engagement/close-loop.ts` discards the read error and returns an empty array. Its public counterpart correctly returns rows and error separately. An operator can mistake an unreadable response record for an empty one. The comment acknowledges the defect but leaves it to a future lane. Fix the behavior and callers together when this outcome is implemented.

This is an extension of working capability. The repository already has campaign links, response entries, a comment matrix, RTP comment-response records, plan review releases, report generation, source freshness and exact package custody. The local project inventory did not justify starting another platform. No new library is needed for these joins. A fresh external engine/library assessment is still necessary before any proposal to replace a modeling engine; this review does not make such a proposal.
