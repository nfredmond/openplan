## Principal finding

The shared Storage path guard accepts a percent-encoded parent traversal that the installed Supabase SDK and native URL parser normalize outside the approved bucket. This is a demonstrated component-level authorization defect. Source tracing connects it to a member-writable model artifact and a service-role signing route. Native end-to-end confirmation is not established, so this report does not claim retrieval of another workspace's bytes.

The parent reviewer reported that automatic tool safety review blocked planned native confirmation and instructed this reviewer to stop further exploit construction, network probes and database mutations. No native security probe was run by this reviewer. Reporting continues from previously obtained source and synthetic evidence. This is a test-coverage limit, not a finding that the application denied the request.

## SEC-01. Encoded parent segments escape the approved Storage target

1. **Severity and confidence.** High severity. High confidence in the helper and SDK target escape, demonstrated with executable synthetic evidence. Moderate confidence in the complete unauthorized download chain because native route/database/Storage execution was not performed.
2. **Affected commit and locations.** Baseline `891a0d89a848133d44b9e4f314a76a922cd71ace`. `openplan/src/lib/models/artifact-source.ts:51–60` compares the raw bucket and prefix and rejects literal `..` only. `openplan/src/lib/files/tenant-scoped-storage.ts:19–29` delegates to it. `openplan/src/app/api/models/[modelId]/runs/[modelRunId]/artifacts/[artifactId]/download/route.ts:113–146` resolves the member-writable reference and passes it to the service-role signer. The same guard protects direct downloads at `artifact-source.ts:81–89`. Native SDK implementation was inspected in installed `@supabase/storage-js/src/packages/StorageFileApi.ts:709–725`, `905–916` and `1495–1497`; dependency behavior is recorded in the evidence, not treated as a repository source change.
3. **Trigger and preconditions.** An authenticated workspace writer controls a model-run artifact `file_url`, uses the approved bucket and their own run prefix, and supplies encoded parent segments after that prefix. A consequential foreign-object read also requires a known target bucket/path, an existing target and the normal configured service-role Storage client. UUID/path discovery was not demonstrated.
4. **Expected versus observed.** The guard should refuse a path whose effective request target leaves the authorized bucket or run. The actual guard accepts the encoded variant. The actual installed SDK prepares a request whose native `Request` path points to the other bucket after normalization. The control using literal parent segments is refused; the legitimate same-run object is accepted.
5. **Consequence.** The service role can be asked to sign a target different from the target the application authorized. This creates a credible cross-workspace artifact-disclosure path. It is not evidence that a foreign object exists, that its path is discoverable, or that native Storage returned its bytes. Ordinary model artifacts are sufficient for the source-level path; this finding does not depend on mutating frozen scientific evidence.
6. **Reproduction and direct evidence.** `evidence/security-storage-traversal.cjs` transpiles the exact helper source without editing it, uses the installed SDK, and captures the normalized URL with a synthetic fetch implementation. `evidence/security-storage-traversal.json` records all results. The execution sent no network request and used only synthetic strings. The sample begins with the approved `run-artifacts` bucket and own model-run prefix, yet the captured request path is `/storage/v1/object/sign/kb-documents/foreign/file.pdf`. The original schema permits a writer's artifact rows through owning-run membership at `20260318000026_model_run_stages_and_artifacts.sql:96–105,136–145`; `20260728000007_workspace_write_role_gate_children.sql:43` adds a writer gate, not target-path validation. The route itself documents member control at lines 113–115. Later scientific custody triggers inspected protect specified retained validation relationships; this review found no general URL-normalization guard replacing the shared helper.
7. **Why existing checks miss it.** `model-run-volumes-artifact-source.test.ts:138–151` checks an explicitly different bucket and an explicitly different run. `model-run-artifact-download-route.test.ts:11,125–130` mocks `createSignedUrl`, so its oracle does not normalize the URL as the installed SDK/network layer does. These checks can reject obvious strings while never examining the effective request target. No claim is made that every repository test was executed or searched exhaustively.
8. **Smallest plausible correction.** Make the shared guard reject noncanonical object-path segments before any privileged read or sign. Compare the canonical request target with the authorized bucket and prefix, or use a strict path alphabet consistent with generated object names. Review percent encodings, separator variants and URL delimiters together. Avoid a decoder that approves one representation while a downstream layer decodes again. No correction was applied.
9. **Regression and mutation evidence.** Add a focused helper/SDK test that checks the effective URL, retains ordinary filenames, and refuses encoded traversal. A native regression should establish permitted same-run access and denied foreign-bucket, foreign-run and revoked-user requests using disposable synthetic objects. Existing synthetic evidence demonstrates a harmless comment control producing identical results. An in-memory candidate that also rejects `%` changes only the unsafe case to refusal; reverting that condition reproduces the exact failed safety expectation. This is a diagnostic candidate, not a proposed complete production implementation. The evidence's process exit indicates the reproduction assertions succeeded, not that application security passed.
10. **Release status.** Released-code path at the recorded baseline. Independent helper/SDK defect, not unfinished synthesis context-history work. No development correction was independently verified in this subreview.

## SEC-02. Artifact Storage insert policies do not enforce the viewer role

1. **Severity and confidence.** Medium severity. High confidence in the SQL policy omission; moderate confidence in effective native Storage upload behavior, which was not executed. Treat this as a source-supported concern pending native confirmation.
2. **Affected commit and locations.** Baseline `891a0d89a848133d44b9e4f314a76a922cd71ace`. `openplan/supabase/migrations/20260420000060_report_artifacts_bucket.sql:43–49` and `20260727000014_grant_application_assembly.sql:500–506`. The role promise is `openplan/src/lib/auth/role-matrix.ts:28`.
3. **Trigger and preconditions.** A signed-in viewer belongs to a workspace and attempts a new allowed-type object in that workspace's path prefix in `report-artifacts` or `grant-application-exports`. The native Storage service and its ordinary role grants must be available.
4. **Expected versus observed.** The viewer role promises read-only access. The reviewed INSERT policies test workspace membership without role. Later restrictive Storage policies found in the migration set protect particular engagement reads and management files, not generic INSERT operations in these two buckets. No live object creation was attempted, so the observation is the policy behavior expressed by the current source.
5. **Consequence.** A viewer can plausibly create workspace-owned files outside the application write gates. This can consume storage and create unregistered artifact objects. Overwriting existing objects, modifying retained report records, or presenting injected bytes as a legitimate report were not demonstrated and are not claimed.
6. **Direct evidence.** Both policies authorize `split_part(name,'/',1)` against all caller workspace memberships. Neither tests `role` or `workspace_member_can_write`. The public-table writer migrations cover application tables, including report artifact rows, but do not add an equivalent `storage.objects` role gate. Source search found no later drop or replacement for the two named INSERT policies.
7. **Why existing checks miss it.** `openplan/src/test/migrations/policy-inventory.ts:141,179` expressly skips schemas other than `public`. The viewer guard consumes that inventory. `rls-viewer-denial.test.ts` tests application-table writes, not Storage uploads. The missing boundary is the Storage schema/service, even if every public-table assertion passes.
8. **Smallest plausible correction.** Restrict Storage INSERT in these buckets to workspace writers, or make creation service-only if every legitimate caller already uses a service-authorized worker. Retain viewer reads where intended. Confirm the actual producer paths before selecting either approach.
9. **Relevant regression check.** Against an owned disposable stack, prove viewer read success, viewer upload denial, member upload success and wrong-workspace upload denial. A harmless policy comment should survive the guard; removing the role check should fail for the upload-specific reason. No new native guard or test was written in this subreview.
10. **Release status.** Released migration policy concern. Not a prototype or known unfinished v1 module. Native confirmation remains open; no verified resolution is recorded.

## Other concerns and ruled-out candidates

### Polymorphic links enforce the owning workspace but not target identity

`plan_links.linked_id` is a bare UUID at `20260315000021_plans_module.sql:16–25`. Its INSERT policy checks only the plan's workspace at lines 131–140. Equivalent program and model link schemas have the same shape. The July 27 cleanup migration intentionally supplies deletion cleanup without target foreign keys. July 28 writer policies restrict the owning parent but not target tenancy.

Application route validation reads targets and compares workspaces. Direct authenticated table writes can bypass that route validation in the reviewed schema. The downstream detail routes also use caller RLS when resolving linked records, which constrains disclosure. No foreign-data read or consequential workflow misrepresentation was demonstrated, so this remains a data-integrity concern rather than a confirmed security finding. A native malformed-target test should distinguish a dangling reference, cross-workspace reference, and legitimate same-workspace link. It should then examine the actual consuming workflow before assigning severity.

### Outbound DNS checks retain an acknowledged connection-time gap

`openplan/src/lib/http/outbound-url.ts:69–89` explicitly documents that validation and connection resolve DNS separately. The implementation checks address families, disallows credentials and non-HTTPS schemes, restricts ports, and rechecks redirects. GTFS reads also cap bytes and use a deadline. Those controls do not establish DNS pinning at connection time. This is an existing acknowledged architectural risk. No DNS rebinding, internal network request, or external provider call was attempted. It should not be counted as a newly demonstrated exploit.

### Historical issues correctly superseded

- The original `gtfs-uploads` bucket permitted any authenticated upload/read. `20260717000082_v1_security_hardening.sql:31–32` drops both policies. It is not a current finding.
- The historical `execute_safe_query` function ran arbitrary SELECT text as a definer. `20260418000058_drop_execute_safe_query.sql` removes the dormant function. It is not a current finding.
- The original engagement public policies authorized share-token existence. July 17 hardening drops those anon policies. Current public read routes filter active campaign/share-token identity and use the public-copy view. Historical enumeration is not a current finding.
- The temporary-schema ordering concern has an explicit later migration, `20261014000032_application_temporary_schema_order.sql`. Reporting an older function header alone would miss that update. This subreview did not execute a full native function ACL/search-path census.
- Workspace member listing deliberately uses service role after owner/admin authorization because member-table RLS exposes only the caller's row. Last-owner race protection also has a database trigger; the preliminary route count is not the entire control.
- Contract snapshot readers distinguish finance and management audiences in later migrations. The reviewed writer/export functions are service-only where actor IDs are supplied. An older owner/admin-only policy alone does not describe current scoped contract access.
