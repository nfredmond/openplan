## SCI-01. Tokenless ActivitySim HTTP worker permits command execution and deletion

1. **Severity: High. Confidence: high.** The actual route executes a caller-selected command and deletes caller-selected synthetic files. External network reachability was not tested.
2. **Affected commits and locations.** Both commits named above. `workers/activitysim_worker/main.py:50-65` accepts executable templates, output paths and force; `main.py:105-113` skips authentication when the token is absent; `runtime.py:529-548` resolves the supplied output directory and recursively removes it; `runtime.py:581-588` prepares that directory before validating the bundle; `runtime.py:758-759,794-800` executes the supplied command. `Dockerfile:15` binds Gunicorn to all interfaces. `DEPLOY.md:16-20,134-141` calls the token optional and documents an exposed Docker port.
3. **Trigger and preconditions.** Run the shipped manual HTTP wrapper without `OPENPLAN_ACTIVITYSIM_WORKER_TOKEN`, with a reachable port. Caller knows an existing bundle directory. A usable configuration allows the executable path; a directory containing `manifest.json` is enough to reach directory preparation. The worker must have permission over the target files.
4. **Expected versus observed.** A remote request without authorization must not reach execution or filesystem replacement. An in-process request with synthetic peer address `198.51.100.27`, no Authorization header and no configured token returns HTTP 200. It removes `synthetic-record.txt` from an unrelated directory and runs a Python command that creates a harmless marker. The response reports `succeeded`.
5. **Consequence.** Anyone reaching this tokenless worker can run commands with worker privileges or destroy files it can modify. No host compromise, external attack or deployed exposure is claimed. The normal `npm run worker:activitysim` polling entrypoint is separate from this HTTP wrapper.
6. **Reproduction.** Run `evidence/science-venv/bin/python -B evidence/science-activitysim-http.py` from this report directory. The script imports the real Flask route and runtime, creates only temporary synthetic files, and records the result in `evidence/science-activitysim-http-result.json`. A configured-token request returns 401 and leaves files intact. The no-op comment mutation preserves the reproduction. Forcing the authorization branch changes the result to 401, caught by the HTTP-result assertion. No listener opens.
7. **Why existing checks miss it.** The 14 `workers/activitysim_worker/tests/test_runtime.py` cases run successfully in this review, but test the runtime directly. They do not test the HTTP authorization boundary or all-interface tokenless startup. Push CI's Python worker job covers `workers/aequilibrae_worker/test_*.py`, not ActivitySim's HTTP wrapper. The optional local worker runner does not substitute for a missing authorization test.
8. **Smallest plausible correction.** Refuse tokenless network operation and require authorization before runtime setup. Mirror or strengthen the existing county-worker fail-closed boundary. Make output roots and executables operator-owned configuration for HTTP use. Refuse `force` replacement outside an explicitly owned runtime directory, including symlink and ancestor cases.
9. **Regression check.** Exercise real HTTP routes with a remote peer, missing/wrong/correct token, valid synthetic bundle, arbitrary output directory and harmless command marker. Assert both response and absence of filesystem/process side effects. Test Gunicorn startup independently from `__main__`. Retain the no-op control and a removed-authentication counterexample.
10. **Release classification.** Shipped, documented optional runtime wrapper. Its name contains "prototype," but it is distributed with a Docker deployment command and actual execution behavior. This is not a new gap in the unfinished synthesis feature. Setting a token prevents this unauthenticated trigger; the unbounded filesystem trust remains an architectural concern for authorized callers.

## SCI-02. County cancellation leaves descendants running and can hold the queue

1. **Severity: High. Confidence: high for surviving descendants and blocked cancellation; medium for an indefinite real modeling job.** The synthetic child survives cancellation and completes its write. An indefinite child was not left running.
2. **Affected commits and locations.** Both commits named above. `workers/county_onramp_worker/main.py:404-421` starts the bootstrap without a separate process group, signals only its PID, then waits without a timeout. `scripts/modeling/bootstrap_county_validation_onramp.py:72-74` launches child commands with `subprocess.run`. Those children inherit the bootstrap's captured output pipes. `docs/ops/KNOWN_ISSUES.md:219` describes cancellation and queue release as corrected under KI-2026-08-24-008.
3. **Trigger and preconditions.** Cancel a running county job while the bootstrap waits for a child process. The child retains inherited stdout or stderr. The default worker has one execution slot.
4. **Expected versus observed.** Cancellation should terminate the owned execution tree and release its slot, or report explicitly that termination remains unresolved. Actual `_run_job` kills the synthetic bootstrap while its child continues. The child writes a marker roughly 1.5 seconds after cancellation. The worker waits for that child before reporting `cancelled`, despite a 0.10-second test grace period. The no-op reproduction behaves the same.
5. **Consequence.** Cancelled work continues computing and writing artifacts. A child that does not exit keeps a pipe open, so the unbounded `communicate()` also keeps the worker slot occupied. The latter conclusion follows from the exercised wait and the missing timeout, rather than an indefinitely running test. No stale callback or cross-attempt artifact overwrite was demonstrated.
6. **Reproduction.** `evidence/science-repro.py` runs actual `_run_job`, replacing only command construction and callback delivery with synthetic owned resources. The parent script uses `subprocess.run` to launch a child that sleeps 1.5 seconds and writes a marker. The review sets the cancel event after child readiness. `science-repro-result.json` records surviving child output, elapsed cancellation time, final status and callback states. A comment-only function copy preserves behavior. Removing the cancel branch produces `completed`; the explicit `cancelled` assertion rejects that counterexample. All synthetic processes exit naturally.
7. **Why existing checks miss it.** The county worker's 10 tests return OK. Its queue-cancellation test uses `FakeProcess` at `tests/test_main.py:225-249`; `terminate()` flips a boolean and `communicate()` immediately returns. There are no children or inherited file descriptors, so that test cannot detect this defect.
8. **Smallest plausible correction.** Start each owned bootstrap in an isolated execution group and terminate its owned descendants, with bounded escalation and confirmed completion. Container execution needs its own owned-container termination semantics; killing the Docker client alone is not proof of stopping its container. Keep attempt identity and unrelated processes protected.
9. **Regression check.** Use a real parent-child process with inherited pipes, assert the child's delayed marker never appears, confirm the second queued job starts, and separately exercise a child that ignores the first termination signal. Include an unrelated control process that remains alive. Remove descendant termination to prove the test detects the defect. A VM/container power-loss drill remains separate.
10. **Release classification.** Released cancellation behavior, with a current known-issue entry claiming the earlier queue problem corrected. This finding narrows that correction's evidence. It is separate from the already listed in-memory ODM recovery risk and long-stage reaper concern.

## SCI-03. Directional observation is compared with both directions and labeled compatible

1. **Severity: Medium. Confidence: high.** The synthetic end-to-end evaluator reproduces the numeric and direction-label errors. No affected published county result was found in the seven retained match audits inspected.
2. **Affected commits and locations.** Both commits named above. `scripts/modeling/validation_instrument_v2.py:400-401` accepts a directional count on any bidirectional link without choosing AB or BA; `:493-496` labels it `one_direction`. `workers/aequilibrae_worker/model_validation_core_v5.py:345-351` loads `PCE_tot` even when directional columns exist. `scripts/modeling/run_comparable_observation_study.py:225-238` derives the modeled direction claim from that match label.
3. **Trigger and preconditions.** A one-direction observation has a unique route/facility-compatible bidirectional link. The CSV has nonzero opposing flow. A source package and match/basis artifacts pass their existing custody checks.
4. **Expected versus observed.** Compare eastbound observations with eastbound modeled flow, or mark direction unresolved. The synthetic observation is 100 eastbound vehicles. The matching link has AB 100, BA 900 and total 1,000. The real file evaluator reports modeled value 1,000 and 900 percent absolute error, and marks direction `compatible`. The correct same-direction residual is zero.
5. **Consequence.** Diagnostics can misattribute opposing flow to model error, distort local diagnosis and misstate quantity comparability. The evaluator still reports `inconclusive`; this is not a demonstrated false scientific pass or nationwide validation claim.
6. **Reproduction.** `evidence/science-repro.py` imports the real matcher and file evaluator, uses an existing synthetic fixture structure, and writes a three-column synthetic volume CSV. Exact temporary file hashes pass the normal gate. `science-repro-result.json` preserves values and direction status. A no-op source clone survives. Replacing the selected-link sum with zero triggers the numeric assertion. `science-source-hashes.json` records the seven frozen audit hashes and zero matching occurrences of this particular trigger; no study was rerun or changed.
7. **Why existing checks miss it.** `scripts/modeling/tests/test_validation_instrument_v2.py:26-83` builds one-direction fixtures whose modeled direction fact simply copies the observation. The tests use one-way geometry or a prebuilt match and only a total-volume CSV. The script returns its normal all-tests-completed result while this reproduction succeeds. It does not test a directional observation against asymmetric AB/BA values on a bidirectional link.
8. **Smallest plausible correction.** Until directional extraction is proven, refuse a one-direction match on a bidirectional link. The complete correction carries the selected AB/BA component and geometric direction through the frozen audit, basis and evaluator; it must not silently change existing frozen studies.
9. **Regression check.** Test eastbound and westbound observations, reversed geometry, asymmetric AB/BA, perpendicular geometry, unavailable directional columns and a combined-direction control. The combined case should use the total; directional cases should use the correct component or remain unresolved. A total-column mutation must fail for the numeric reason.
10. **Release classification.** Released instrument defect with a synthetic trigger. The sampled published v0.41 audits do not establish affected published metrics. Keep the frozen records and any successor instrument/version distinct.

## Verification record

The reviewer created two reproduction scripts, their JSON outputs, two existing-suite logs and source hashes under `evidence/science-*`. A private Python 3.12 environment contains Shapely, Requests, Flask and python-dotenv. The root scripts use `-B`; no application source or frozen artifact changed. `git status --short --untracked-files=no` was empty after the work.

Existing scripts returned 10 county tests and 14 ActivitySim runtime tests OK. The validation-instrument script also completed. These are narrow supporting checks, not acceptance. The new evidence checks each have a surviving no-op and a specific behavioral counterexample; they do not infer fault detection from a blanket nonzero process exit.

Recommended order: close SCI-01 before any use of the manual HTTP wrapper; repair and test process-tree cancellation before relying on long county-run recovery; then correct the directional instrument before a successor observation study. National validation, borrowed behavioral coefficients, unfilled preregistration fields, source-supported uncertainty and practitioner acceptance remain acknowledged work. None is promoted into a new released defect merely because v1 requires it.
