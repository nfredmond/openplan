## Retain the proposal in a new review revision

`import_thematic` is a distinct, reasoned staff command. It names the exact
expected review parent and checksum, thematic request, selection sequence,
history manifest, proposal and final capture. The server reconstructs the whole
proposal through the current staff member's authenticated history access.
Incomplete selections, changed hashes and a different source are refused.
Cancelled work and departed requesters remain available as retained history;
import never grants another provider call.

The resulting staff draft retains the complete original proposal and history
text in `machineOrigin`. This includes contextual evidence, original citations,
unassigned reasons and earlier uncertainty. The original interpretation stays
`machine_unreviewed`. A subsequent staff correction preserves those exact texts.
Another explicit import creates another revision; earlier drafts and imports
remain immutable. Draft title, notes and groups come from the selected proposal,
so the receiving interface must show the replacement before the staff command.

Every imported revision is replayed from its original history when reading a
review chain. An opaque reference or a recomputed review checksum is insufficient.
The review, approval and response-link servers carry the private evidence reader
explicitly. Existing category-only reads remain supported. The category editor's
working-copy format refuses an import command until its dedicated recovery flow
is implemented. Routes continue to refuse agent write headers; this operation
does not add agent write authority.

Migration `20261015000010` extends the existing service-only review writer. It
adds no table and never rewrites an earlier approval. Its transaction checks
current staff, source/request scope, a retained selection sequence, the actual
selected final capture, immutable evidence hashes and the exact current parent.
It also prevents a normal correction from changing machine evidence or ordinary
creation from claiming a machine proposal. Original semantic replay remains the
TypeScript reader's responsibility. Database hashes alone do not establish it.

Existing approval events continue to identify their original revisions. The new
revision remains unapproved until a separate exact-version staff action. A
response link cannot inherit an earlier draft's approval.
