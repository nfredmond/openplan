## What the reader establishes

A service worker can now replay one chosen context under the new thematic
requester's current native authority. It uses named preparation commands. It
neither fabricates a staff client nor grants fresh execution to an earlier author.
The native scope checks the new requester's role, campaign, cancellation, source,
parent, chosen context and authorship. Each selection page rechecks that scope and
reads its sequence from retained bindings. The caller cannot substitute another
request or sequence. Private helper functions remain unavailable to clients.

The application reads the original source after establishing native authority.
It checks exact selected columns, scope, source hash and creation time. Parent
results, stored context frames, original provider responses and predecessor
chains use the same reconstruction code as current-staff history inspection.
The two entry points retain separate native access and pagination functions.
Before returning, the worker reader rechecks current authority and immutable
identities, then compares the complete history, final capture and result against
the chosen hashes. Incomplete or changed input fails. Earlier cancellations may
arrive during inspection without changing original content or authorship.
