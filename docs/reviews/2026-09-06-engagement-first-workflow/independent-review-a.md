## Concrete findings

### A1. Legacy mapped contributions disappear from GeoJSON

`openplan/src/lib/engagement/review-export.ts:61` renders a contribution with a valid `longitude`/`latitude` fallback when `geometry` is null. Lines 164 onward build `contributions.geojson` by requiring `readStoredEngagementGeometry(row.geometry)` and then exporting only `row.geometry`. An older coordinate-only record therefore appears on the report map and remains in snapshot JSON but disappears from the GeoJSON companion. The promised complete contribution geography is inconsistent between deliverables.

Smallest correction: use one validated geometry resolver for PDF and GeoJSON, preferring stored geometry and falling back to a WGS84 Point only when both coordinates are valid. Keep non-map records explicitly non-map. Do not fabricate coordinates for them. Reconcile mapped IDs independently against the frozen snapshot, including a legacy coordinate-only row and a written-location-only row. A harmless title edit must preserve this check; removing the fallback must fail it.

### A2. Historical survey answers still use current question meaning in the visible dashboard

`openplan/src/lib/engagement/survey-responses.ts:504-526` reads approved answers without their retained configuration version. `aggregateCampaignSurvey` at 998-1013 loads the current published definition, groups every answer by question ID, then applies today's prompt, options, type and configuration. The page calls this at `openplan/src/app/(app)/engagement/[campaignId]/page.tsx:293`; `survey-results-panel.tsx:37-39,59-60` displays the resulting count, prompt and option labels. The assistant has a second caller at `openplan/src/lib/assistant/chat-tools.ts:1367`.

Concrete consequence: changing a rating maximum from 10 to 5 silently drops prior ratings 6-10 because `survey.ts:1028` accepts values only up to the current maximum. Renaming an option attributes earlier choices to the new wording. Removing a published question removes its older result section. The new export can retain original definitions while the ordinary campaign dashboard tells a different story.

Smallest correction: extend the confined approved-answer reader with the session's configuration version, without exposing respondent/session identifiers. Load immutable definitions and group by version plus original question ID. Use that version's prompt/options/type/configuration. Add a configuration version field to `SurveyQuestionAggregation`, and a composite rendering key so repeated question IDs do not collide. For records without retained configuration, show the recorded answer count and unavailable historical interpretation. Do not apply the current numeric scale as a fallback. A visible missing-definition group is preferable to silently dropping old responses. Test a renamed choice, changed numeric scale and archived question through the actual page data, not only the export builder.

This is basic meaning preservation required by CORE-ENG-02/04. It does not require advanced theme extraction, inference or a new results module.

### A3. Public contribution labels also lose original category meaning

`openplan/src/lib/engagement/public-portal-data.ts:1019` reads approved items without `configuration_version_id`. Lines 1171-1195 send current categories and each item's current category ID to the portal. The public reader cannot distinguish the category shown when the participant contributed from its later renamed label, even though immutable definitions now exist.

Smallest correction: select each item's version, load relevant definitions once and carry an original category label plus an explicit availability state into the portal item type. Show the category when submitted separately from current staff classification and filters. This preserves legitimate recategorization without rewriting what the participant originally answered. A no-definition older response must remain unavailable, not be relabeled from today's definition. Check both the map/sidebar and equivalent non-map detail, including a renamed or retired category.

### A4. Reused setup omits language and alternate-participation settings

`openplan/supabase/migrations/20260908000007_engagement_setup_reuse.sql:20-23` copies campaign instructions, type and place, but omits `default_content_locale`, accessibility contact/alternate-format fields, and the submission-geofence setting. The same function copies content translations at lines 49-51. Configuration capture explicitly retains these campaign fields in `20260908000002_engagement_configuration_versions.sql:31-38`. The reuse component says dates, project links and participation start fresh but does not identify the lost language/contact settings.

This is a source-established omission with a product-choice component, not a proved data leak. Reusing a non-English consultation can retain its translated material while dropping the source-language setting. Clearing old contact details can be appropriate when responsibility changes, but the planner needs to see and review that reset. Preserve language metadata with copied content; either retain assistance/geofence settings for explicit review or disclose their reset in the reuse summary and preview. Keep the new campaign private with draft questions and hidden layers. A contrasting non-English, constrained-access reuse case would settle whether the resulting workflow remains understandable and safe.

### A5. Retained download controls are promising but need route-by-route live proof

The reviewed `review-export-download.ts:11-27` uses the authenticated client's job lookup, checks campaign/report/artifact identity, rechecks public copies through `publicReviewStillCurrent`, verifies downloaded bytes and streams with `private, no-store`. `survey-responses.ts` checks current contribution content/status, thread parents, survey session status, answer contents and published staff responses. `20260908000008_engagement_export_access_paths.sql` denies direct snapshot-column reads, narrows internal-report metadata to staff and prevents authenticated raw Storage reads for Engagement review objects. `project-evidence-bundles/bytes.ts:122-123` calls the common controlled download before copying a report artifact.

These mechanisms address real bypass risks. They are not yet my live proof. Before accepting privacy, exercise Campaign download, Reports artifact download, project evidence bundle, direct PostgREST job snapshot access, direct Storage download/signed URL, viewer and revoked-membership access. Withdraw/redact a included contribution, parent, survey answer and staff response after the report is complete. An old public review must become unavailable through every path, while authorized restricted custody remains retained.

One policy boundary remains to state explicitly: historical configuration includes context-layer geometry, instructions and translations. `publicReviewStillCurrent` checks response copies, not withdrawn context layers or changed campaign descriptions. Decide which configuration withdrawals require retiring a public review. I did not establish a current exploitable leak from this boundary and do not elevate this inference into a proved defect.

## The ten required questions

1. **What would make this the ultimate free planning operating system?** A planner should carry one defensible case from inherited sources through work, public review, authorized decisions, delivery and later reuse. Each person should understand what they received, what remains unresolved and what they can actually rely on. Complete practice breadth, all-state substance, California depth, independent ownership and separate scientific validation remain mandatory. This workflow contributes retained public evidence to that case; it does not satisfy the destination by itself.

2. **Can every kind of US planner do their core work?** No. The current matrix and roadmap retain incomplete OWP administration beyond bounded preparation, full RTP inheritance/update, land-use authority/development cases, transit/freight/BCA/TDM depth, environmental and agency civil-rights programs, aerial production, capital delivery and reimbursement, contract forecasting, municipal program reporting, grant pursuit, procurement, hosted adoption and substantial agent work. Smaller/tribal/community organizations remain unassessed in complete cases. The need is complete jobs joined across existing owners, including offline/assisted engagement and authoritative hearing records beyond a web map.

3. **Does every state work in substance?** No current evidence establishes that. The matrix marks California partial and every other state/DC unassessed for the full contract. A geometry picker or honest unsupported disclosure is not substantive planning support. The Engagement primitives should remain geography-neutral, but national language, rural connectivity, public-record responsibilities, sovereign authority and administrative practice require observed cases. No new country-specific core type is warranted here.

4. **Is California the gold standard?** No. California still lacks complete cases across its agency types and geographies. A complete-streets demonstration and countywide wayfinding demonstration are useful engineering cases, not evidence for coastal, metropolitan, tribal, border and state-agency practice. OWP preparation does not establish adoption/approval or reimbursement; a consultation does not establish a statutory hearing. Preserve those distinctions.

5. **Are both travel models scientifically validated for every published use?** No. `docs/modeling/ACTIVITYSIM_RUNTIME_GAP.md` proves a dated executable run and names its structural assumptions. `docs/ARCHITECTURE.md` and `docs/ops/KNOWN_ISSUES.md` retain transferred-coefficient and inconclusive nationwide evidence. No Engagement change alters that. Keep AequilibraE and ActivitySim separate; public-input counts are not representative travel-demand observations, and model agreement cannot rescue an unsupported use or failed geography.

6. **What simple overlooked idea has the largest effect?** Treat every view of a contribution as a view of the same historical planning record. The export now retains original meaning, but the ordinary dashboard and public category display still reinterpret it. Carry version-aware meaning through those existing readers. This gives the participant, planner and recipient a consistent account without adding another module. Then carry the same identifier into reviewed agency responses and project decisions in M9b.

7. **Which old rule or decision is wrong now?** The prior OWP direction record cannot stand as current evidence for these substantive Engagement changes; the failing guard is correct. The older newest-200 feed diagnosis must be updated only after current completeness behavior is exercised, since this branch now uses complete paged reads. A generic assumption that published question IDs retain fixed meaning is wrong once editable definitions and retained versions exist. Conversely, the whole-v1 and human-competitive-evidence boundaries are still correct. Do not weaken them to make this milestone pass.

8. **What should be removed, joined or deepened before adding anything new?** Remove the divergent geometry and historical-definition interpretation paths. Deepen the existing campaign, survey, report and project evidence joins. Reuse the Documents worker and Reports artifact store, as this branch does. Preserve a single controlled Engagement-download path across Reports and bundles. Do not add a standalone consultation system, new task system or second artifact archive. The current code establishes a coherent existing home, so a broader new-product search is unnecessary for this correction.

9. **What would prove these recommendations wrong?** A source trace or live test showing that every submitted answer is already grouped by its immutable definition would falsify A2; the inspected reader lacks the required fields. A public renamed-category journey preserving original wording would falsify A3. A coordinate-only fixture whose PDF and GeoJSON IDs reconcile would falsify A1. Reuse that retains source language or deliberately discloses every reset could resolve A4. Privacy claims require actual denied accesses through all named routes. A comparative task study with practicing planners and participants, accessible equivalent tasks, measured setup/review effort and repeatability could establish M9c; it cannot be replaced by my preference for this architecture.

10. **What is the highest-leverage next completed outcome?** Finish and retain the authorized first Engagement case, including the fixes above, two contrasting campaign setups, public participation, review/redaction/withholding, recoverable immutable PDF/XLSX/ZIP delivery and project handoff. Do not replace the sole roadmap with this report's own competing queue.
