# Private engagement decision links

Staff can connect a campaign response to a decision already recorded in Projects.
The link retains the reviewed project decision, response revision, referenced
contributions and available submission configurations. This is private evidence
of the connection. It does not approve a project decision or publish an explanation.

## Record the connection

1. In Projects, open the project, choose Record and record the proposed or settled
   decision with its rationale. Use the actual decision status.
2. In Engagement, open a campaign linked to that project and choose Setup.
3. In You said / We did, create the staff response and select the contributions
   it addresses. Staff meeting input can use the existing Register feedback item
   form. Keep missing source information explicit.
4. Choose Connect responses to decisions. Select the staff response and project
   decision, then Review current sources.
5. Read the retained response revision, decision rationale and source references.
   Enter a reason for the connection and choose Save decision link.

The source words are observed when the link is reviewed. They are not a claim
about what the contribution said at the earlier time the staff response was first
written. A missing submission configuration remains unknown or unavailable.

## Correct or withdraw a link

Open Retained decision history and select the link. Changes to the response or
project decision do not rewrite the original link. Review current sources again,
record the reason and save a reviewed correction. The correction retains its
predecessor and a new source snapshot.

Withdraw link, keep history records why the link is no longer current. The
original and corrected evidence remain available. Neither operation changes the
project decision itself.

## Recover an interrupted request

An unconfirmed save may already exist on the server. Download retained request
preserves the browser copy. Retry exact request uses the same identity and checks
for its original receipt instead of creating a duplicate.

If a copy is damaged or the request needs to be closed, choose Review request
recovery or Review damaged request recovery. Review the proposed resolution and
preserve its download. Confirm resolution and preserve copies checks the native
outcome. An existing saved link keeps its original evidence. An unsaved request
is cancelled, so a late save using that identity cannot arrive afterward.

When both the page and browser storage hold different copies, recovery preserves
both. It saves and reads back an archive containing the copies and verified server
receipts before retiring matching active copies. A different copy changed by
another tab remains available for review.

If the resolution response is lost or the archive cannot be written, download the
retained resolution and retry the same resolution. Keep the page open while its
copy is needed. A damaged resolution has its own Review resolution recovery
control, which preserves those damaged bytes and resolves the original request.
An original request that remains afterward can be reviewed separately.

Archived decision recoveries provides downloads for the current signed-in
account, workspace and campaign. Each archive contains the exact request and
receipt identities and checksums. Archive numbering is a display position, not
chronological order. Retain the downloaded files when preserving evidence outside
the browser; clearing browser storage removes its local copies.

## Current limits

Public decision explanations and decision lineage in campaign reports/exports
remain unfinished. Private snapshots must not be used as public payloads.
Planner Agent writes to this workflow are refused; staff use the browser controls.
Unsent form fields are not promised to survive a page reload. Native recovery
protects retained requests and confirmed history, and requires current staff
access. Browser storage does not provide an atomic transaction across tabs.
