# v0.36 project evidence bundle proof

Date: 2026-08-26

Status: release candidate verified.

## What this proves

The project Evidence/Documents surface can prepare a retained, immutable evidence snapshot without treating it as approval or publication. The candidate review is project- and workspace-scoped, explicitly selected by a person, revision-locked, and capped at 500 visible candidates. Generation refuses partial output when selected evidence is stale, missing, out of scope, too large, or no longer matches its recorded checksum or custody state.

The ZIP is deterministic and always carries the canonical manifest, checksum file, README, project record, current project GeoPackage, linked-data provenance, and project-linked modeling evidence. Selected source files use the same tenant-scoped byte resolvers as their individual download routes. Artifacts over 50 MiB or beyond the 100 MiB/200-file generation limits remain disclosed as reference-only manifest entries.

The core contracts are country-neutral. The end-to-end verifier deliberately used a stored Wellington, New Zealand project place and added no FIPS field or US-only geography selector.

## Live browser evidence

Chrome was confirmed against this checkout at version 0.36.0 before the test. Through the visible Projects interface, the test created `v0.36 Evidence Bundle Browser QA`, stored a country-neutral Wellington location (`-41.28664`, `174.77557`), opened Evidence/Documents, reviewed the mandatory GeoPackage, confirmed the exact selection, froze the retained artifact, and downloaded it as `openplan-project-evidence-2026-08-26.zip`. The ready bundle appeared immediately in Prior bundles with its date, 6 KB size, zero optional files, ready status, manifest hash prefix, and download action.

The first live freeze attempt correctly returned the visible stale-review refusal after the project location changed. That exposed a UI defect: Prepare opened an inventory cached before the change. Prepare now refreshes the candidate inventory before opening review, while the server-side stale guard remains intact.

The desktop dialog was visually inspected and screen-reader-visible state exposed the dialog name, required GeoPackage label, explicit sensitive-file confirmation, cancel action, and disabled/enabled freeze state. Keyboard testing exposed a second defect: forward Tab could leave the native dialog after the final control. The shared modal now wraps focus in both directions; the corrected live sequence was confirmation, Cancel, Freeze evidence bundle, Close, then confirmation again. A deliberate mutation disabling this trap failed the focused reachability test.

At a 390 by 844 viewport, the page had no document overflow (`scrollWidth` 390), the review dialog stayed fully inside the viewport (about 352 by 674 pixels), and the selection, warning, confirmation, Cancel, and Freeze controls remained readable and reachable. The desktop and phone screenshots were captured from the live app. Console inspection found no feature errors; the desktop session recorded one Mapbox style-reload warning while the map was initializing, and the fresh phone session recorded no warnings or errors.

The exact 6,378-byte browser download was then opened outside OpenPlan. `sha256sum -c` passed all six hashed contents, `jq` read the v1 manifest and its explicit source, retrieval, custody, claim-tier, inclusion, uncertainty, and known-limit fields, and `ogrinfo` opened `project_location` with one WGS84 feature at the stored Wellington coordinate.

## Database and custody

Migration `20260826000002_project_evidence_bundles.sql` was applied to the local stack. Ready or failed rows are immutable and cannot be deleted directly. The project deletion cascade remains possible only through a parent-triggered cascade. Owners, admins, and members may create; viewers may review candidates and download ready bundles but cannot create retained artifacts. Storage is private at `<workspace>/<project>/<bundle>.zip`.
