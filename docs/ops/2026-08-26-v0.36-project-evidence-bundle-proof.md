# v0.36 project evidence bundle proof

Date: 2026-08-26

Status: release candidate verified except for the real-browser visual gate and remote CI.

## What this proves

The project Evidence/Documents surface can prepare a retained, immutable evidence snapshot without treating it as approval or publication. The candidate review is project- and workspace-scoped, explicitly selected by a person, revision-locked, and capped at 500 visible candidates. Generation refuses partial output when selected evidence is stale, missing, out of scope, too large, or no longer matches its recorded checksum or custody state.

The ZIP is deterministic and always carries the canonical manifest, checksum file, README, project record, current project GeoPackage, linked-data provenance, and project-linked modeling evidence. Selected source files use the same tenant-scoped byte resolvers as their individual download routes. Artifacts over 50 MiB or beyond the 100 MiB/200-file generation limits remain disclosed as reference-only manifest entries.

The core contracts are country-neutral. The end-to-end verifier deliberately used a stored Wellington, New Zealand project place and added no FIPS field or US-only geography selector.

## Database and custody

Migration `20260826000002_project_evidence_bundles.sql` was applied to the local stack. Ready or failed rows are immutable and cannot be deleted directly. The project deletion cascade remains possible only through a parent-triggered cascade. Owners, admins, and members may create; viewers may review candidates and download ready bundles but cannot create retained artifacts. Storage is private at `<workspace>/<project>/<bundle>.zip`.
