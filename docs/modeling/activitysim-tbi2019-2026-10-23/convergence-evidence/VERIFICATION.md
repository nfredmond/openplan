## Native controller capture failure and recovery

The first unchunked reference completes with exit code zero and seven final
model tables. ActivitySim's startup log cleanup deletes the controller's
`stdout.log` because it sits inside the model output directory. The controller
then raises `FileNotFoundError` while hashing that missing file. The retained
`run-parity.log` records the exception; the lost stdout bytes remain unavailable.
The engine's own log, final tables and scope-health receipt survive.

`parity-baseline-recovery.json` binds that completed reference to exact final-file
hashes and its surviving scope receipt. `resume-parity.py` checks those hashes
and skips replay of the completed reference. It writes later stdout outside the
engine output directory. The same capture correction applies to the full-arm
recipe. Input, engine, coefficient and model-configuration bytes do not change.
`execution-closure.json` pins these post-archive recipes. The `.archived.py`
copies match the original archive inventory, preserving the failed orchestration
path. The archive itself remains unchanged and contains the earlier recipes.

This exception is a capture failure, not a numeric parity result. The source
campaign does not exercise process-launch or stdout-cleanup lifecycle behavior;
this native observation establishes that separate boundary. Recovery does not
restore the lost stdout or its unavailable outer-controller elapsed time.

## Export-identity instrument correction and numeric stop

The original comparator assumes the first exported column is the row identity.
Real exports put named IDs later in their schemas, so the comparator refuses the
household table before completing the comparison. The retained
`parity-result.identity-assumption.json` and `activitysim_chunk_parity.archived.py`
preserve that instrument failure. Corrected fixtures put IDs after another column,
reject missing and duplicate named IDs, and add a targeted first-column regression
mutation. No model is rerun for this correction.

The named-key comparator then finds two one-ULP differences in the modeled trip
`destination_logsum` column. `parity-result.json` and `parity-failure-detail.json`
retain that numeric failure. Further model execution stops. Production, SEMCOG
parity and both full arms are unexecuted, not successful or failed full runs.
The final source mutation campaign has 31 accepted controls; archive metadata
controls add five, for 36 total. Exact restoration applies to disposable source
copies, and no incidental test errors occur in the accepted campaign.
