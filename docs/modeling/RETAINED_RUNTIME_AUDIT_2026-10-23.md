scientific interpretation remains invalid. The original five development input

## Scope and counting

This inventory covers every tracked file under `docs/modeling` and `data/modeling`,
including compressed assessments, results, closure manifests, locks and evidence. It also covers
review records containing AequilibraE, ActivitySim or NumPy under `docs/reviews`.
`scripts/research` has no retained output; the three `scripts/research` Python
modules are source, and their retained outputs appear under `data/modeling`.
The machine-readable [inventory](../../data/modeling/s2-runtime-audit-2026-10-23/inventory.json)
binds every included file by SHA-256 and extracts exact JSON runtime fields.
Five original development run summaries supplement the tracked records.

Counts below use **file records**, not independent experiments. A lock, its result
and its report can describe one execution. `yes` means an identified susceptible
runtime is used or directly reported, not that every number in that file is
wrong. `no` excludes this specific Python 3.14 defect, not all numerical defects.
`unrecorded` means the execution-bound pair or its susceptibility is not established.
A recorded version mention, Docker base, traceback or today's interpreter is
not substituted for a missing historical runtime. Frozen `.json.gz` assessment records
are read as published evidence, never changed or recomputed. Closure manifests
are read without opening the sealed source archives they identify. No sealed input or held-out source is opened.
Published evidence records are read for this inventory only; no outcome is
recomputed, selected, repaired or regraded.

   scientific comparisons. The recorded rejection remains intact and grants no
   advancement. Convergence and exact repeat do not establish measurement units.

   covering seven counties and two methods. This is not the measured 2.0.2 pair.
   Their engine version fields originate in retained evidence packets, through
   `run_development_validation_study.py:305`. This audit does not inspect consumed
   source workspaces to prove each stage's executable or native-library bytes.

   not declared corrupt or safe. Published baseline raw APE includes 100%,
   96.1%, 98.1%, 2.4%, 6.0%, 329.3% and 18.5%; later comparable-observation and
   structural diagnoses inherit the baseline provenance limit. These records
   do not feed the cordon experiment.

   That pair is outside this specific defect. The 2017 successor closure and
   other records without execution-bound runtime stay `runtime unrecorded`.
   No acceptance source or consumed holdout is reopened.
4. The historical one-county calibration selection APE of 62.80% to 43.29%,
   followed by a rejected 46.25% trial, has no execution-bound pair in the
   retained report. It is **runtime unrecorded**, not confirmed affected and
   not cleared. It is not independent accuracy and does not feed cordon demand,
   calibration, advancement thresholds or baseline scores.
5. Review records include Python 3.14 launcher, lease and custody controls.
   These often use inert numerical modules or no engine. They are not evidence
   of a susceptible scientific extraction. Python 3.11 lightweight worker checks
   and graph fixtures likewise establish their stated narrow boundaries only.
   No past hosted production run is confirmed affected. Hosted inventories and
   deployment history remain uninspected.

does not extend that measured result to every NumPy release or interpreter.
